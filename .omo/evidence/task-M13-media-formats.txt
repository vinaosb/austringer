DEPENDENCY DECISIONS (executor's pick, recorded per plan; cargo-deny VERDICTS)
-------------------------------------------------------------------------------
Extract = lopdf (over pdf-extract), generate = krilla 0.8.2 (plan first choice).
Full rationale recorded in harness-media/src/adapter/pdf.rs module docs. Summary:
- lopdf exposes the full needed DOM surface (pages/version/Info/outline depth/fonts
  WITH embeddedness/images/encryption) AND a text decoder covering BOTH simple-font
  encoding tables AND Type0 fonts via their ToUnicode CMaps (the round-trip fidelity
  surface). pdf-extract is text-only and would drag a second lopdf copy.
- CARGO-DENY FORCED ONE DEVIATION FROM THE PLAN TEXT: the plan named "lopdf 0.40.0",
  but cargo deny flags RUSTSEC-2026-0187 (stack overflow in load_mem via deeply
  nested objects - this adapter's EXACT untrusted parse surface; fixed in 0.42.0).
  Pinned lopdf 0.42.0 instead. deny.toml records the pin rationale at the dep.
- CARGO-DENY IGNORES (documented in deny.toml with rationale): RUSTSEC-2026-0206
  (rustybuzz unmaintained) + RUSTSEC-2026-0192 (ttf-parser unmaintained). krilla
  0.8.2's simple-text shaping is rustybuzz-backed with no 0.8.x upgrade path; both
  are unmaintained-not-vulnerable and touch only the trusted-spec shaping path, never
  untrusted input parsing. Revisit when krilla migrates to harfrust.
- cargo deny check: advisories ok (with the two documented ignores), bans ok,
  licenses ok, sources ok.
