  events). Vendor files:
  - anthropic.rs     POST /v1/messages; tool_use blocks (index->call_id map),
                     message_start+message_delta usage merge (cache_read/
                     cache_write), stop_reason map (end_turn/stop_sequence/
                     max_tokens/tool_use/refusal), ping/message_stop skipped.
  - chat.rs          chat-completions codec shared by openai/xai/compat:
                     data-only frames (event name IGNORED by design - pinned
                     by test), tool_calls index->id correlation, finish_reason
                     map (stop/length/tool_calls/content_filter), usage chunk
                     w/ prompt_tokens_details.cached_tokens. FINISH IS
                     BUFFERED + flushed at end-of-stream: usage arrives AFTER
                     finish_reason on this wire; the consumer always sees
                     usage-then-finish.
  - openai.rs        OpenAiAdapter::chat (/v1/chat/completions) and
                     ::responses (/v1/responses) - both stable public
                     surfaces, no feature gate needed.
  - responses.rs     Responses API: output_text.delta, output_item.added
                     (function_call items), function_call_arguments.delta
                     (item_id correlation), response.completed (usage +
                     finish; ToolCall when function items streamed),
                     response.incomplete (max_output_tokens->Length,
                     content_filter->Refusal), response.failed -> StreamError.
  - google.rs        :streamGenerateContent?alt=sse; parts[].text, functionCall
                     parts -> SYNTHESIZED stable ids gemini-call-{n} (API

  - xai.rs           chat wire at api.x.ai. compat.rs: configurable base URL
                     ({base}/chat/completions), NoCredentials-friendly

  HTTP error mapping: {"error":{type|status|code,string-or-numeric}} across
  all five vendors -> ProviderStreamError::Http{status,code,message};
  non-JSON bodies degrade to a 300-char snippet. 429/5xx retryable, 4xx fatal

Auth (src/auth/): CredentialSource trait (credentials() + kind()),
  AccessToken{value: SecretString (Debug-redacted), style, kind, expires_at},
  AuthHeaderStyle {Bearer, XApiKey, XGoogApiKey, None} -> header rendering;
  StaticApiKey (x_api_key/bearer/google_api_key), NoCredentials.
  OAuthDeviceFlow (RFC 8628 + PKCE RFC 7636 S256, sha2+base64ct, form-encoded
  over the injected Transport): begin_device_authorization (PKCE challenge
  when configured) -> poll_for_token (authorization_pending/slow_down typed;
  refresh_token persisted) -> refresh() (rotation-aware) -> credentials()
  cache->refresh->LoginRequired; invalid_grant/expired_token -> ReauthRequired.
  OAuth error bodies classified even on HTTP 200 (proxy-mangled statuses).
  SecretStore trait: InMemorySecretStore (default, process-local) +
  KeyringStore behind NON-default feature "keyring" (windows-native/
  apple-native/sync-secret-service; refresh tokens in the OS store only when

  AuthKind {ApiKey, Subscription} = billing surface, exposed via each

  HUD (todo 42) reads adapter.auth_kind()). No provider client ids are baked
  in - DeviceFlowConfig is configuration-owned.

RISKS / NOTES
-------------
  - Cost tables are a point-in-time snapshot of published list prices;
    runtime overrides are the correction path (by design, documented).
  - transport_reqwest.rs is intentionally untested by the suite (zero-network
    house rule); correctness rests on the seam contract shared with the
    tested in-memory transports. A live smoke test belongs to the evals
    adapter (todo 42/34), never the unit suite.
  - Chat-completions test frames carry an inert `event: message` line the
    real endpoints omit (T2 SseEvent DSL renders event+data). The codec
    ignores event names by design for this family - parsing equivalence is
    total over the data payload; noted here for honesty.
  - Gemini tool-call ids are synthesized (gemini-call-{n}); stable within a
    response, which is what start/delta correlation needs.
