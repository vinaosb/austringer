## What landed

harness-media `ffmpeg` feature (dependency-free - all codec work in the
opt-in external tool):

- `src/adapter/ffmpeg/policy.rs` - the codec-clean licensing anchor
  (constraint 7): typed `Target` vocabulary (GREEN-only, by
  construction), RED_CODEC_NAMES table (h264/libx264/hevc/h265/
  libx265/aac/libfdk_aac/theora), refused-target strings with named
  reasons (H.264/H.265/AAC = RED; mp4 remux = deferred lane digest
  section 6), TranscodeSpec {target, caps{max_width,max_fps,
  max_audio_kbps}, trim{start_secs,end_secs}} parsed with
  deny_unknown_fields (the injection guard: no spec string ever
  reaches argv).
- `src/adapter/ffmpeg/argv.rs` - the FIXED argv template set: typed
  spec -> words; {input}/{output} staging tokens; every other word a
  digest-section-4 literal or validated number. Test-pinned over every
  target x cap x trim combination.
- `src/adapter/ffmpeg/census.rs` - ffprobe `-show_format
  -show_streams -of json` -> typed AvProbe (streams{codec_type,
  codec_name, width/height, fps, duration, sample_rate, channels,
  bitrate}, format/duration/bitrate) + canonical sorted-key tree +
  bounded text projection. 64-stream parse cap -> typed
  ExtractTooLarge.
- `src/adapter/ffmpeg/ops.rs` - Adapter{tools, env} over the M15
  ToolExecutor: probe_av / transcode (RED line enforced: stream-copy
  remux of RED payloads = typed UnsupportedFeature; decode-away legal)
  / thumbnail (first frame -> PNG; audio-only = honest Ok(None)) /
  pcm_md5 (`-map 0:a -f md5 -`) / extract_av (census + thumbnail into
  the caller's MediaStore, every artifact carrying ProducerInfo).
  Staging: session-temp files named m17-{in,out}-<pid>-<n>.<ext>,
  published to the child as HARNESS_MEDIA_STAGE_IN/OUT (mocktool
  contract; real ffmpeg ignores), cleaned on success AND failure.
- `src/adapter/ffmpeg/verify.rs` - verify_transcode: probe(before/
  after) structural diff on DECLARED targets (codec identity from the
  target's census table, stream census, unordered /streams), lossy
  duration tolerance max(1 frame at the EFFECTIVE output fps, 1%).
- `tests/ffmpeg_adapter.rs` (18 hermetic tests, mocktool lane) +
  `tests/ffmpeg_real.rs` (#[ignore], FFMPEG_BIN env, never CI).

## Deviations / notes

- Producer command disclosure in the MOCK lane shows the substitution
  triple (the override argv replaces the real one by design), so the
  codec-flag disclosure is pinned by the argv-word-universe test and
  the real-tool tier instead.
- The transcode target vocabulary includes OggVorbis + WebpLossy
  (fixed quality 80, still-image) beyond the plan's container list:
  both are digest-section-4 GREEN flags the M14/M28 redirects name
  this lane for. libaom-av1 rides the allowlist as MkvAomAv1Opus.
- OpRequest dispatch still refuses opus/webm/mkv extract/generate (the
  request kinds carry no staging contract / MediaStore); the adapter
  surface (probe_av/extract_av/transcode/pcm_md5) is the M31
  engine-tool seam, and the refusal text + descriptor reasons now say
  so.
- M16 (blend) shares this checkout: its in-flight mocktool.rs /
  executor.rs / adapter.rs / manifest.rs / capture.md edits were
  excluded from this commit by staging HEAD+M17-only blobs
  (worktree-preserved); its staged index was left untouched.
