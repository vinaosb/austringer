DESIGN DECISIONS (justifications required by the task brief)
-------------------------------------------------------------------------------
- Placement harness-exec/src/preflight/ (not a new crate): the plan's own
  commit prefix for todo 22 is `feat(exec)`; pre-flight is the consumer
  of T14+T19/20+T21 and the natural home is the command-runner crate;
  ZERO root Cargo.toml changes (harness-ast/harness-vfs/serde/serde_json
  are path/workspace deps already in the tree); dependency graph stays
  acyclic (exec -> ast, vfs). Blocks T23 cleanly.
- rustfmt via `cargo fmt --check` invocation, NOT the rustfmt lib crate:
  the library API is unstable across releases and would add a dependency;
  the cargo surface is the stable one, is workspace/rustfmt.toml-aware,
  and rides the same probe/timeout/kill-tree discipline as every other
  adapter through the CommandRunner seam.
- Corrective-cycle interpretation of "default = surface-after-2": the
  cap (<=2 fixer invocations) is structural; the default SurfaceAfterTwo
  policy returns no edits, and an empty fix set is a PROVABLE no-op
  (pipeline deterministic) so identical reruns are skipped — surface
  happens after the initial run without wasting cold cargo checks.
- Single-slot semantics: only ONE failure object exists at surface time
  (each failed iteration replaces it); the composite carries primary
  first + <=8 structured errors + total count.
- PTY screen text as extraction source: T19's ExecOutcome is bounded by
  design (window law) — the binding brief names this the T19 bounded-
  output discipline. The brace-balanced scanner makes JSON extraction
  wrap-tolerant; very large error floods degrade to the bounded window +
  total count, which IS the compact-rejection contract.
