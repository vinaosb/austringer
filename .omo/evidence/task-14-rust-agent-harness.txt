## Design decisions + justifications
- Default feature set = rust, toml, json, bash (4 grammars): keeps every default build to four C
  compilations and covers the file types a Rust agent harness touches most (its own sources,
  Cargo/config, manifests/lockfiles/tool output, build scripts). Bash replaces the plan's suggested
  markdown: the crates.io tree-sitter-markdown 0.7.1 still binds the tree-sitter facade directly as
  a NORMAL dep (pin ^0.19), which trips cargo's one-copy `links = "tree-sitter"` rule against the
  0.27 facade (verified: resolver error before any grammar compiled).
- Feature surface = exactly 50 languages: 4 default + 46 behind `langs-extra` (also individually
  via `lang-<name>`; `dep:` wiring keeps unselected grammars out of the build graph entirely).
- Grammar-crate selection rule (documented in lib.rs + Cargo.toml): only crates whose `language()`
  returns tree-sitter-language's `LanguageFn` (ABI-stable, version-independent). Rejected for
  legacy direct-facade bindings (normal-dep facade pin): markdown, kotlin, dockerfile, sql, scss,
  vim, vue, svelte, org, bibtex, wgsl, perl, clojure, vimdoc. tree-sitter-latex 0.1.0 additionally
  references an external scanner (src/scanner.c) it does not ship — unresolvable externals at link
  time; replaced by solidity (verilog was already in, latex dropped). tree-sitter-toml-ng replaces
  the abandoned tree-sitter-toml. Everything verified live against the crates.io API (versions,
  licenses, dependency kinds) before pinning.
- Tags engine: hand-rolled over the facade's own Query/QueryCursor (capture convention
  `@name.definition.<kind>` / `@name.reference.<kind>`, optional `@_span` container) instead of the
  tree-sitter-tags crate — that crate pins its own facade version, drains names through a buffer we
  would immediately re-extract into serde types for the cache anyway, and hardcodes the old
  `@definition.X`+`@name` pairing. ~150 lines own the convention outright; TagTable is directly
  serde-serializable into the cache. Query predicates (#eq?) are used where grammars need them
  (elixir def/defmodule, scheme define).
- is_error()/is_missing() are DISTINCT flags (discovered empirically: tree-sitter's has_error() is
  true for MISSING-only trees; an unbalanced '(' yields MISSING ")" with NO error region, while an
  unclosed '{' at EOF yields one ERROR region). Diagnostics: 1-based line, 1-based byte column,
  capped at 200 with truncation flag; walk is iterative (stack-safe; verified with 20k-deep
  nesting).
- Cache: one JSON entry per file, keyed blake3(canonical path), validated by blake3(content)
  + length; stored mtime is a fast-path hint refreshed on hash-preserving touches. Corruption =
  silent miss + rewrite (torn/garbage/outdated-version all tested). Writes are temp+rename.
  Store failures degrade to CacheStatus::StoreFailed, never errors (cache is an accelerator).
- No-grammar degrade: unknown extension OR known-language-without-compiled-grammar both return the
  typed AnalyzeOutcome::NoGrammar { path, language: Option<LanguageId> } — never Err, pipelines
  fall back to text tools (both shapes tested).

## Adversarial classes
- malformed_input: 4KiB XorShift64 garbage bytes → is_error, diagnostics bounded <=200, no panic;
  invalid UTF-8 in comment parses clean; invalid UTF-8 inside an identifier → lossy name, no panic;
  huge source (64MiB+1) → typed FileTooLarge { path, size, max }, never a parse.
- stale_state (cache): edit → hash changes → Miss + new tables (asserted by name content); delete
  cache dir → rebuild (Miss + 1 entry on disk again); corrupt entry file (torn garbage w/ NUL+0xFF)
  → silent Miss + correct tables restored; outdated cache version (v:999) → Miss + re-stored as
  current version; identical-content rewrite with new mtime → still Hit (hash authoritative) +
  mtime refreshed in entry.
- flaky_tests: deterministic fixtures only; full default suite run 3x, identical results; timing
  asserts use wide CI-safe bounds with actuals recorded via eprintln (above).
- hung_or_long_commands: durations recorded — full langs-extra cold `cargo check` on this
  workstation ≈ 16s wall (48 grammar C compilations, INCLUDE workaround active); incremental
  full-feature test runs 1–4s; default-suite runs 0.5–1.5s; isolated worktree cold suite 23s;
  release bench build + run <60s. All bounded, none hung.
- misleading_success: tag tests assert symbol names, kinds, byte-span slices back to the source
  text (span == name bytes), container-span containment, and reference span content — never bare
  counts; langs-extra fixtures assert expected def names per language.
- new_input_parsing: weird-but-valid (deep 20k-block nesting completes, iterative walk, no stack
  overflow; empty/whitespace sources yield empty tables; broken sources still extract parseable
  symbols); query match-limit guarded (TAG_MATCH_LIMIT, truncation flag on TagTable).
- dirty_worktree: git status distinguishes this task's files (harness-ast/**, root Cargo.toml +5
  anchored dep lines, Cargo.lock) from the parallel todo-18 worker's harness-lsp/** files and .omo
  state; commit stages only this task's files (lock committed whole as derived data, same policy
  as task 17). Isolation worktree run (above) proves the workspace red is not ours.
- resource_leak / subprocess / network / injection / authz / crypto / PII: N/A — pure local
  library, no subprocesses, no network, no secrets (cache stores only file-derived symbol data).
