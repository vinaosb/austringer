## What landed (plan todo 15, all six scope points)
1. FILE GRAPH from tag tables — `graph::FileGraph::build((path, TagTable))`:
   files sorted by path (stable node ids regardless of ingestion order, tested);
   edges = same-symbol cross-file references (def-file ↔ ref-file, UNDIRECTED),
   weight = referencing file's reference count.
2. PERSONALIZED PAGERANK d=0.85 on CSR — `pagerank::solve` over a compressed-sparse-row
   adjacency (row_offsets/col_indices/weights flat Vecs; NO Vec<Vec> adjacency anywhere);
   personalization = uniform mass on focus set (`uniform_on`); dangling mass redistributes
   to the personalization vector (standard); L1 tolerance configurable (default 1e-8) +
   iteration cap (default 200) + converged/iterations surfaced; iteration order fixed →
   bit-deterministic (tested).
3. REFS-BY-NAME (forge Lattice §26) — the cross-reference index is
   `BTreeMap<String /*symbol name*/, SymbolLinks>` where SymbolLinks carries def sites
   (path + kind) and ref counts keyed by FILE PATH. No node id appears anywhere in the
   index; ids exist only inside the derived CSR and never outlive a build → renames /
   renumbering cannot dangle an edge. Locked by
   `rebuild_after_rename_and_reorder_edges_survive_via_name_keys` (hub file renamed +
   ingestion order shuffled → same links, same weights, via name keys).
4. SIGNATURE-ONLY rendering — `path:` headers + indented `name:kind` lines
   (TagTable carries no signature text today, so the binding's "else name+kind"
   degradation applies; a signature column slots into the same line later); `    ...`
   after cut symbol lists, `...` at column zero after a cut file list; render(0) = ""
   (no ellipsis-only noise). Ordering: rank desc → path asc → symbol name asc (ties by
   kind label) — all exact-content tested.
5. ≤1k-TOKEN budget via BINARY SEARCH on density — density d = top-d files AND d symbols
   per file; token counting = chars/4 rounded up (deterministic approximation, unicode
   scalars not bytes — documented + exact-tested); binary search finds the LARGEST d
   whose render fits (cost monotone in d, tested); search space tops at
   max(file count, max per-file defs) so single-file repos can still raise symbol
   density (bug caught by a red test, fixed); budget configurable (default 1000).
6. Acceptance — 10k-file synthetic map ≤1k tokens AND <50 ms cold render (numbers below).

## Design decisions + justifications
- UNDIRECTED edges (binding text says "def-file ↔ ref-file"): both the definer of the
  focus files' symbols and the referrer of the focus files' exports are map-relevant
  neighbors; undirected personalized PageRank is the standard proximity measure.
  (Aider's directed ref→def variant biases mass toward popular definer files;
  undirected keeps neighborhood semantics for focus expansion.)
- MULTI-DEF-SITE RULE: every referencing file links to EVERY file defining the name,
  each edge carrying the full reference count. Rejected alternatives: "highest weight"
  (undefined before ranking exists) and directory proximity (breaks on re-exports and
  moved modules, arbitrary tie-breaks). Mirrors aider's proven behavior; fully
  deterministic; tested (2 def sites + 1 referrer ⇒ both edges weight 2.0, def sites
  NOT linked to each other).
- Names kept in the index only when they actually produce a cross-file edge — external
  symbols (std-lib calls with no repo def site) and same-file-only symbols stay out
  (tested), keeping the 10k-file index lean.
- Malformed-input handling is typed/bounded, never panicking: empty names skipped +
  counted (`skipped_empty_names`), duplicate same-file defs collapse to one def site
  (first kind wins), self-references produce no self-edges, duplicate input paths keep
  the FIRST table + count (`duplicate_paths`), short rank/personalization vectors read
  missing entries as 0, out-of-range focus ids skipped, unknown focus paths counted in
  `focus_matched` with uniform fallback. NO unwrap/expect/panic in library code.
- SIMD DECISION: scalar f64, justified by measurement. The power iteration is
  gather/scatter bound over sparse adjacency (induced scatter into the rank vector),
  not FLOP bound — SIMD lanes do not accelerate irregular indexed scatter. Measured
  (release, this machine): 10k nodes/200k edges converge in 16 iterations with
  build+rank+render = 1.63 s TOTAL (render-only 21.3 ms); 50k nodes/3.15M edges
  converge in 14 iterations inside a 15.1 s total that is dominated by the
  BTreeMap/String/PathBuf-heavy graph BUILD, not the solver. An explicit SIMD path
  would add complexity (and likely unsafe) for no user-visible win at any size the
  plan budgets; revisit only if a real-repo profile shows iteration dominating.
  The known cost center for todo 35 is incremental graph reuse (cold full rebuild is
  the expensive part at 50k scale).
- Determinism: fixed CSR iteration order, splitmix64-seeded generator, sorted-path node
  ids, BTreeMaps throughout — same inputs give byte-identical maps (tested at the
  facade with 500-file repos and via 3 identical full-suite runs).
