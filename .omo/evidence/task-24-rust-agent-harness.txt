CONSOLIDATION DECISION (deferred to T24 by T8's ledger) — rusqlite-everywhere
-------------------------------------------------------------------------------
Chosen: (a) rusqlite-everywhere; sqlx dropped. Justification:
1. T8's rusqlite 0.40 + bundled already compiles on this exact machine (task-8
   evidence INCLUDE workaround; task-24 re-verified: FTS5 is compiled into the
   bundled amalgamation — probe below). sqlx would add a second SQLite wrapper
   API, async runtime weight, and its own bundled C build for zero capability
   gain in this crate.
2. The sessions store is synchronous by design (SQLite IS its concurrency
   model: one connection, WAL, busy_timeout); the daemon wraps it in async at
   the boundary (same pattern T8 set).
3. Plan wording "sqlx SQLite ... (goose pattern)" is honored in substance:
   schema versioning + atomic up-migrations exist (PRAGMA user_version,
   single-transaction apply) and the registry adds what goose lacks here —
   mandatory DOWN steps with both-direction round-trip tests per generation
   (the dsh v3 lesson). Divergence from the literal "sqlx" is documented here.
Probe (scratch project, this machine, INCLUDE workaround active):
  rusqlite 0.40 bundled: CREATE VIRTUAL TABLE t USING fts5(body) OK,
  bm25() rank = -0.000001 → FTS5 ships in bundled. Recorded in evidence.

-------------------------------------------------------------------------------

  sqlite-vec.c at line 3772 does `#include "sqlite-vec-diskann.c"`, which is
  NOT packaged in the crate (cc-rs: fatal error C1083). Packaging bug.

  `sqlite3_vec_init()` taking zero args — not the extension entry point;
  cannot register vec0 with a connection.
Per the task's fallback clause: the vector dimension is implemented behind
`VectorIndex` (vector.rs) with an FTS5-only default (all vector scores 0.0,
blend arithmetic unchanged) + `InMemoryVectorIndex` (exact cosine) for tests
and caller-supplied embeddings. A vec0-backed impl drops in later without
touching callers. Disclosed for verifier adjudication.

RISKS / RESIDUAL
-------------------------------------------------------------------------------
1. sqlite-vec fallback (disclosed above): hybrid retrieval ships FTS5-only by
   default; the InMemoryVectorIndex exercises the full blend/MMR path in
   tests. Production embeddings need a vec0 impl (blocked on upstream
   packaging) or an external vector service behind VectorIndex.
2. Encrypted sessions are excluded from the FTS index by design (indexing
   plaintext would defeat encryption-at-rest); disclosed in lib.rs + store
   docs. Memory notes are plaintext curated knowledge by design.
3. Encrypted-session retention archives are SKIPPED with a typed report
   entry (no key available to write a plaintext cold file); callers archive
   explicitly after keyed export. Documented in retention.rs.
4. Debug perf asserts use x10 budgets (strict in release); evidence timings
   above are from the release run.
5. The workspace-scaffold smoke test in harness-sessions was replaced by the
   real crate tests (56) — not deleted to pass, superseded by the crate.
