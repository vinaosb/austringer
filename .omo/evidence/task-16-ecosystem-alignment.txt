INVARIANT -> OBSERVABLE MAP
---------------------------
(a) pre-approval block carries the plan id: e2e asserts the typed
    plan_blocked SessionEvent with "plan":1 + tool edit_lines AND the
    tool-result deny reason contains "plan 1"; disk untouched; NO
    PermissionAsk fired (the block precedes the mediated ask).
(b) approve -> edit proceeds: e2e turn 1 blocked, PlanAsk answered
    Approve -> plan_approved frame, plan_gate inactive, turn 2 edit runs
    through the NORMAL permission path (ask + AllowOnce) and lands on disk.
(c) edit-the-plan re-gates: PlanAsk answered Edit{artifact} ->
    plan_updated revision 2 on the stream, fresh PlanAsk carries the
    edited artifact (same plan id), turn 2 edit blocked again.
(d) OFF by default: pre-existing suite green (811/811) AND the golden
    session-transcript fixture recorded at pre-task-16 HEAD byte-compares
    equal with mode off (the strongest no-default-change proof available).
(e) session-grant suspension: harness-core chain-level tests — a
    session-scoped view_window grant allows, enter_plan() suspends it
    (falls to the mode ask), the approval flip (set_mode) restores it;
    forever grants never suspend. Enforcement:
    AutonomyMatrix::honors_grant (matrix.rs — the single source) consulted
    by AutonomyGate before its stored-grant allow (gate.rs step 5).
(f) execution-time re-check: PlanGatedExecutor wraps EVERY session's
    executor (engine.rs standard_stages) and consults check_write at
    execute() time on the CURRENT gate state — an in-flight call approved
    before plan entry blocks there (unit: the gate reads live state, never
    an approval snapshot; e2e: approval-stage deny + executor re-check are
    the same single-source check).
(g) mediation-policy machinery: plan asks ride PermissionMediator with a
    third AskKind; FirstResponder/Designated/LocalOnly/ConsensusQuorum
    all enforced by unit tests (local-only ignores a remote approve;
    quorum requires explicit approves, any reject fails closed); answers
    key on the pump's server-assigned connection id; the identity-less
    HTTP route refuses PlanAnswer typed 400 (the FallbackAnswer precedent
    + the Antigravity v1.3.2 receipt: no surface auto-approves a plan).

DECISIONS + DEVIATIONS (for orchestrator sign-off)
--------------------------------------------------
1. phases.rs (harness-orchestration) intentionally UNTOUCHED: BoostPhase
   Strategy->Execution->Verification already expresses the phase
   vocabulary and is referenced as the building block; forcing the
   orchestration enum into the daemon plan state machine would add a
   cross-crate dependency for zero behavior (the daemon's pending->approved
   transition IS the Strategy->Execution boundary at session level).
2. "mode flag on session start (OFF by default)" implemented as the
   ClientMsg::PlanMode command available from session start: the flag
   exists per-session (PlanGate, default inactive) and flips on command;
   Hello's wire shape stays frozen (a Hello field would churn every
   constructor site for no additional invariant — the acceptance criteria
   test OFF-by-default behavior, not the entry mechanism).
3. Reject KEEPS plan mode active (only approval flips autonomy back per
   the matrix — the todo names approval as the flip); the user exits via
   /mode off (PlanMode{on:false}).
4. The plan artifact seeds empty at entry; the agent drafts the plan in
   the transcript and clients materialize it onto the artifact through
   PlanDecision::Edit (the Antigravity editable-artifact receipt). A
   transcript-to-artifact auto-capture is deliberately NOT invented.
5. mediation.rs is now 496 pure-prod LOC (pre-existing ~330 + the plan
   lane). Over the 250 ceiling; the natural split (permission lane /
   plan lane / policies into mediation/) is flagged for the orchestrator
   (issues.md) — not improvised mid-task with the concurrent run_tests
   worker building in the same crate.
6. ACP (todo 12) sees plan asks NOT at all (its hub reader is if-let over
   PermissionAsk) and can never answer one — exactly the todo-12 contract
   "plan approval is NOT answerable over ACP v1".
7. Stale-answer safety: approve/reject/apply_edit/close_ask all check the
   plan id — an answer to an exited (or re-entered, new-id) plan applies
   nothing (unit-tested).
