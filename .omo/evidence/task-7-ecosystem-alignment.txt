## Scope

- `harness mcp list` / `scan` — render `harness_mcp::manager::scan_directories` (parse-only, zero connections)
- `harness mcp serve` — `harness_mcp::server::HarnessMcpServer` over stdio, standalone typed-refusal seams
- `harness mcp call <server>` — smoke: scan by name -> `McpClient::connect` -> list tools (or one `--tool --args` call)
- Must NOT auto-enable any MCP server: every spawn is an explicit user command; list/scan never connect.

## Design decisions (recorded for reviewer)

1. `scan` is a clap VISIBLE ALIAS of `list` (plan wording "list|scan" = one operation; todo 23 wants plain verbs).
2. Entry state renders the MANAGER's own policy surface (`ScanReport::autostart_for` -> `start:on-first-use` | `start:autostart`). `ServerEntry` carries NO enabled/disabled field — none is invented (todo 6's disabled declarations will render honestly once the manager's config shape carries the field).
3. `serve` runs BEFORE daemon transport resolution: mcp commands are daemon-less (no token file needed). Implemented as an early `if let Command::Mcp` borrow-check in `dispatch`.
4. Standalone seams: `harness_ask`/`session_*` tools answer typed `SurfaceError::Engine` refusals naming what is missing (no daemon operator / session surface). No scripted fake data.
5. Typed failure: new `CliError::Mcp { detail }` (`"mcp error: ..."`), pinned by tests at unit + binary level.
6. Manifest change (the ONE allowed): `async-trait` moved dev-dep -> dep in harness-cli/Cargo.toml (impl of harness-mcp's `#[async_trait]` seams AskSeam/SessionControl; crate already in workspace + already compiled for this crate's tests). harness-mcp was ALREADY a dependency of harness-cli (doctor) — no dep addition needed.

## No-auto-enable statement

list/scan are parse-only (manager::scan_directories reads files; zero connections, zero spawns).
serve serves THIS process over stdio; it reads no config and spawns nothing.
call spawns exactly the one server the user named, after an explicit scan hit.
No MCP server is enabled, trusted, or started by any other path in this change.
