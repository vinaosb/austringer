    `app.rs` is a pure headless state machine: `step(event) ->
    actions`, zero timers, zero sleeps on the UI path; the binary's
    loop (`main.rs`) blocks on a std mpsc recv and draws ONLY when

    the daemon's 300 s idle timeout). Idle proof pinned by test
    (§2 idle.rs): 100 000 no-op key events + 100 000 Pong messages =>
    renders stay at exactly 1 (the initial draw) and the batch
    completes < 2 s; the loop's wait primitive (recv_timeout) is
    proven to PARK by test. Must-not-poll-render holds by
    construction AND by test.

    expand transcript/tools/team, ctrl+4 hides the HUD line
    (`app_input.rs toggle`); collapsed headers render "v name (N)"
    counts (`render.rs accordion`).
 3. HUD — `hud.rs`: context gauge (chars/4 estimate vs window,
    saturating %, honest n/a until transcript text exists), cache-hit
    % (last reported), per-model cost rows + routing-savings estimate
    (Devin /session-stats pattern), money aggregated at CENT precision
    (round on every apply; billing-exact ledger is todo 34's job).
    Honest-unknown posture: fields the protocol does not feed yet
    render as explicit n/a/unpriced — never invented numbers. The
    `HudUpdate` struct is the typed seam where todo 34/40 usage events
    will land.
 4. "omnibar @file/@symbol/@git + /mode /rewind /skill" — `omnibar.rs`:
    mention grammar (@file: default, @symbol:, @git:), typed Parsed
    variants incl. Malformed{usage} + UnknownCommand; bounded
    completions from a pluggable CompletionSource; `complete.rs` wires
    @file: over the `ignore` crate walker (gitignore-respecting,
    require_git(false) so non-repo dirs still honor .gitignore,
    2000-walk + 20-result caps, forward-slashed paths).
    @symbol:/@git: stay honestly empty until the LSP bridge (38) and
    git plumbing supply real candidates.
 5. "y/a/n gates" — modal permission gate on `ServerMsg::PermissionAsk`
    (typing is swallowed while open); y/a/n map to protocol
    AllowOnce/AllowSession/Deny answers, c maps to PermissionCancel;
    `PermissionResolved` clears the gate and records a dim note for
    EVERY resolution incl. other clients' answers and Timeout.
 6. "team grid visualization" — `transcript.rs` reduces
    WorkerClaimed/WorkerHealed into WorkerCells; `render.rs` draws the
    queue/worker/alive grid sorted deterministically inside the team
    accordion.
 7. "streaming markdown" — `markdown.rs`: chunk-boundary-IDEMPOTENT
    renderer (pure function of accumulated text; empty lines dropped
    so a trailing-\n chunk never renders a phantom row). Headings
    bold, fenced code shared code style, quotes italic, lists
    bullet-rewritten with indent kept. `StreamDoc` is the streaming
    feed point.
 8. "keybind config" — `keys.rs`: 16-action vocabulary with ONE
    action->name table (ACTION_NAMES), chord grammar
    ("ctrl+alt+delete", "f12", "X"), TOML `[keys]` overrides applied
    ATOMICALLY (failed load leaves the previous layout intact), typed
    errors (Malformed/UnknownKey/UnknownAction/Duplicate).
 9. CLIENT — `client.rs`: WS attach client for
    /s/{sid}/attach?token=..&after=.. ; typed Hello handshake; replay
    cursor (`after` = max frame id seen) reconnects; capped retry (3
    failed connects -> park for manual ctrl+r); protocol violations
    (3 malformed server frames) are FATAL — a reachable-but-hostile
    server is not retried blindly; Bye => clean Dropped + reconnect;
    typed failures Unreachable/Refused/Protocol.
10. Mid-run steering (client side): submit while a turn is running
    sends SessionCommand::Steer (signal-with-start semantics live in
    the daemon), Submit otherwise — pinned by unit test; the daemon
    side was already T35-verified.
11. Binary `main.rs` — crossterm raw mode + blocking reader thread
    (read error = EOF -> Shutdown), client bridge thread, multi-thread
    tokio runtime (2 workers: the UI thread parks in recv for long
    stretches, so the client task must keep its own worker), render
    batching (drain all pending events, then one draw), terminal
    restore on every exit path. Args: --url (http://127.0.0.1:port),
    --session, --token-file (default .harness-daemon/daemon-token —
    the daemon binary's documented handoff location).
