PLACEMENT + DESIGN DECISIONS (disclosed)
-------------------------------------------------------------------------------
- NEW CRATE harness-wasm (workspace member), depending on harness-core only.
  Justification per task brief: plugin TOOLS register through T6's
  ToolProvider trait which lives in core; a dedicated crate keeps the engine
  out of the daemon (and every default build) while giving the runtime a
  first-class home. Daemon consumption is a later todo.
- SIMPLIFIED WIT (per plan binding text "not full WIT tooling"): wasmtime
  v38 (WASI-0.2-era engine line) CORE modules - not components - with a
  fixed versioned ABI table documented in harness-wasm/src/abi.rs (regions:
  input @4096/4KiB, output @8192/4KiB, NUL-terminated JSON manifest @16384/
  8KiB; exports memory + tool_call(tool_id,len); host imports under
  "harness": log/read_file/write_file). Compile-time const asserts pin the
  region layout disjointness.
- FIXTURES IN WAT (the task's RECOMMENDED path): rustup has no wasm32 target
  installed; rather than rustup-target-add or committing opaque prebuilt
  binaries, all 14 fixtures are WebAssembly text - wasmtime's `wat` feature
  parses them natively. Zero toolchain changes. Fixture set:
  good/good2 (echo, hot-reload v2 marker), fuel_hog (infinite loop),
  mem_hog (grow-to-cap), cap_hog (process-exec), old_iface(0)/new_iface(2),
  bad_manifest, no_manifest, garbage, fs (rw read+write tools),
  fs_ro_break (runtime RO write), traversal (../ escape), lie_result
  (claims 9999-byte output).
- HOST-MEDIATED PREOPENS (divergence from WASI fd preopens, documented):
  file access goes through typed host fns that resolve VIRTUAL paths
  ("<scope>/<relative>") with canonicalize+containment; the guest has NO
  other syscall surface. "Nothing else visible" is enforced by construction.
  Write path: mode denial BEFORE any fs probe; target need not exist (only
  the parent is canonicalized; file name validated as one safe component;
  backslash injection rejected).
- CAPABILITY MODEL (Zed §23): manifest declares from
  {process-exec, download, package-install} (none = empty). Declared-but-
  ungranted = typed CapabilityNotGranted at load (no silent escalation).
  Interface 1 binds no host fns to these capabilities - they are a
  declaration contract future interfaces bind to real surfaces (documented
  in manifest.rs + crate docs).
- INTERFACE LADDER (Zed 10-WIT-versions lesson): abi::negotiate supports
  range [INTERFACE_MIN..INTERFACE_MAX]=[1..1]; too-old -> InterfaceTooOld
  ("rebuild the plugin"), too-new -> InterfaceTooNew ("upgrade the host");
  adding v2 = new Interface arm + MAX bump, old dispatch arms never removed.
- HOT RELOAD: PluginHandle snapshots the current Arc<LoadedPlugin> per call,
  so swaps apply to NEW calls only; in-flight calls finish on their pinned
  instance; a FAILED reload keeps the old instance serving (typed
  ReloadOutcome::Failed). Watcher = len+mtime polling (poll_once for
  deterministic tests + PluginWatcher::spawn thread with ReloadEvent
  channel; guard stops+joins on Drop).
- PER-CALL STORES: every tool call gets a fresh Store+instance - fuel
  (default 10M, configurable) and the 32 MiB ResourceLimiter are per-call
  by construction; leaks cannot leak across calls.

RISKS / NOTES FOR LATER TODOS
-------------------------------------------------------------------------------
- Per-call instantiation cost (fresh Store per call): the safe default for
  a plugin surface of this scale; a pooling/instance-cache is a measurable
  optimization for later if profiles demand it.
- ABI v1 I/O bound is 4 KiB each way (== T6 IoCap::DEFAULT inline cap);
  larger plugin results need interface 2 (documented in abi.rs ladder).
- One WasmEngine per PluginHandle today (fine at handfuls of plugins);
  sharing one engine across handles is trivial if ever needed.
- Capabilities bind no host fns in interface 1 (declaration contract only,
  documented); process-exec/download/package-install surfaces arrive with
  the interfaces that actually offer them.
- Watcher fingerprint = len+mtime; content-hash fingerprinting is the
  hardening step if plugins ever swap at identical length within mtime
  granularity (fixtures differ in length, so tests stay deterministic).
- Full-workspace cold check not run (window); workspace resolution + the
  affected crates' suites are green from the committed tree.
