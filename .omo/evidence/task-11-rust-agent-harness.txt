Design notes:
  - [0,L0) = system+effort line + T6 base-schema render; the ToolSchema
    segment content is asserted byte-identical to
    ToolRegistry::render_base_schema (T6 render reused verbatim).
  - [L0,L1) = rules+skills typed slots. The T5 FocusChain::render() API
    fits as-is: reused (not reimplemented) as the rules slot pinned at
    epoch start; mid-epoch todo flips go IN-HISTORY per the epoch doctrine.
  - Volatile tail = last user message ONLY; the tail is exempt from the
    volatile scan and bounded typed at 64 KiB.
  - Layout-law subtlety (tested + documented): the closing history fence
    ("\n</history>\n") is necessarily rewritten once history grows, so the
    next turn preserves the previous prompt only through its stable
    CONTENT end (L2 - fence). RenderedPrompt::cacheable_prefix_bytes()
    exposes that offset; the tracker's chain-break floor and the realistic
    provider-hit expectation both use it.
  - History is NOT volatile-scanned: append-only user/model data may
    legitimately contain historical dates (stable bytes, not injections);
    the scan covers harness-composed frozen segments only (documented).
