## Design (the media pattern, generalized)

harness-media/src/tool/executor.rs `sandbox_gate` is validate-policy ->
typed ToolError::SandboxDenied{ViolationEvent} -> nothing spawns, with env
redaction enforced at the command seam and NO unclaimed kernel isolation
(the module's honesty rule). Todo 4 generalizes exactly that shape onto the
command lane:

1. Per-command policy (harness-daemon/src/tools/safety.rs `command_policy`):
   SandboxTier::Readonly, no roots, egress EgressPolicy::none() (the allowlist
   starts EMPTY — deny-all), EnvScrub::default(). Fail-closed validate()
   parity with media's sandbox_gate (an unsanctionable policy blocks).
2. Egress guard — NEW seam in harness-safety (src/egress/guard.rs,
   `guard_command`): segments the command via perm::commands::split_compound
   (every segment judged independently — `npm i && curl evil` never rides an
   allowed prefix), detects egress-shaped program words (curl/wget/ftp/sftp/
   scp/ssh/nc/ncat/telnet/ping, path- and extension-normalized), reduces
   destination tokens to (host, port), verdicts against the policy. Pure
   string-pattern matching: the guard never opens a socket.
   FAIL-CLOSED: unsegmentable command, egress program with no parsable
   destination, or an unresolvable destination token are ALL denials.
3. EnvScrub at the spawn seam — harness-exec ExecSpec gains
   `env_scrub: Option<EnvScrub>`; spawn_pty (both cfg arms) removes dropped
   variables (additions AND the inherited ambient set — portable-pty's
   CommandBuilder base IS the full ambient) via env_remove. Dependency
   direction exec -> safety is the sanctioned one (windows_sandbox.rs
   documents it).
4. Requested-vs-enforced in the RESULT: every allowed run appends
   `render_report` (IsolationReport::diff over the PTY lane's HONEST enforced
   summary: network=UserlandProxy — the guard; env_scrubbed=true — the seam;
   fs_write/fs_read=Isolation::None — NAMED GAPS, never papered over) and
   names the OS backend resolved via platform_backend() (doctor-parity
   attribution: backend=windows-appcontainer on this machine). A blocked run
   renders the typed ViolationEvent plus "requested: ... enforced:
   blocked-before-spawn (deny honored)".

### Why the OS-backend consult is attribution, not an enforce() attempt

The PTY spawn lane (todo-3's contract: bounded screen-delta rendering) is not
the sandbox backend's spawn lane (SandboxedChild has wait/kill_tree only, no
PTY/output). Attempting platform_backend().enforce() per command and denying
on refusal would (a) make an echo hostage to per-command AppContainer profile
creation, and (b) on Landlock-less Linux (linux_sandbox REFUSES, by design)
break the suite cross-platform — while enforcing nothing, since the child
still spawns through the PTY. Borrowing the backend's kernel-isolation
report for a PTY spawn would claim isolation that was not established — the
exact dishonesty harness-rs isolation reporting exists to prevent. The OS
lane stays owned by the EXISTING safety suites (escape_windows.rs runtime
restricted-token tests, all green in the full run below); doctor keeps
probing platform_backend() passively, unchanged. Observation recorded here
for todo 31: doctor's "backend: <name>" line now agrees with the
`backend=<name>` field in every execute_command result.
