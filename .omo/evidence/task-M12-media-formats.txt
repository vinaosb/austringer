PLAN-PREMISE CORRECTION (recorded; gates strengthened, not weakened)
---------------------------------------------------------------------
The plan's "Khronos glTF-Validator (pure Rust, hermetic, runs IN CI)" premise
is FACTUALLY WRONG, verified during research: the KhronosGroup glTF-Validator
is DART (github languages: 455 KB Dart, 0 Rust); the only crates.io
`gltf-validator` crate (0.3.0, KittyCAD) downloads a prebuilt foreign binary
from GitHub releases AT BUILD TIME (reqwest+tar+xz build-deps), shells out at
runtime, has NO Windows support (build.rs early-return), and takes a path, not
bytes. None of that is admissible in hermetic CI (standing constraint 5: zero
network in the PR path; zero unpinned tool downloads).
In-CI gate (hermetic, pure Rust) - all pinned in tests/gltf_roundtrip.rs:
  1. M5 structural diff vs the INDEPENDENT spec->tree projection (empty=PASS),
  2. full re-parse through the khronos-ecosystem reader (gltf::Gltf::from_slice,
     validating) on EVERY generated artifact - third-party code path, breaks
     writer/reader circularity,
  3. gltf-json's own spec-validation sweep enforced zero-error before emit.
Real-tool tier (#[ignore], never in CI; constraint-5 cadence): the Khronos CLI
binary over every generated GLB, errors=0 pinned. Run at-todo-time on the dev
machine: downloaded win64 2.0.0-dev.3.10 to %TEMP% (never the repo) and ran:
  GLTF_VALIDATOR_BIN=... cargo nextest run -p harness-media --run-ignored only
    --test gltf_roundtrip        -> 1 passed (numErrors=0 across the corpus)
  The tier EARNED its place immediately: it caught two real writer defects the
  circular gates could not (see FIXES), both fixed and re-verified.
