WHAT LANDED
-----------
All in harness-cli only (daemon route shapes consumed read-only, no daemon source touched):
1. cli.rs: SessionsCommand gains `List` (unit variant) and `History(SessionsHistoryArgs)`
   (positional session id); doc/help strings follow the t11 per-variant convention (route +
   --url requirement). Sessions enum doc updated to "todo 11 search; todo 22 list/history".
2. src/sessions.rs (the t11 module, extended): shared `http_surface(spec)` (base + bearer
   token, missing --url => the SAME typed transport hint, now worded "sessions commands")
   and `send_typed(request)` (200 => body, 401/403 => Auth, other => Protocol with the
   daemon's typed error body). The three verbs:
   - `harness sessions list`  -> GET /sessions ({"sessions":[...]}) => one line per live id
     ("no live sessions" + exit 0 when empty).
   - `harness sessions history <sid>` -> GET /s/{sid}/history (bare RunRecord array) =>
     one line per row `[n] automation=<id> fired@<minute>m outcome=<outcome>` with
     ` verdict=<v>` appended on completion rows ("no runs recorded ..." + exit 0 when the
     session is live but unrun). The sid is percent-encoded as a path segment (reuses
     client.rs's encoder, now pub(crate)) — session ids are graphic-ASCII and may contain '/'.
   - search refactored onto the same helpers; behavior byte-identical (typed 400 path
     unchanged).
3. render.rs (flagged over-ceiling file, additions kept surgical):
   - Event::Condensation now renders: "~ condensed through seq <n> — <first summary line>"
     (was `None` — the INVISIBLE bug this task names). Event::Snapshot stays None (the task
     names only Condensation).
   - New `ndjson_line(msg)`: event frames take the envelope shape, EVERY other ServerMsg
     passes through verbatim — the single place expressing "NDJSON passes ALL v2 frames,
     never a filtered subset". run.rs print_msg's json branch now calls it (net smaller).
4. client.rs: SessionTransport enum -> struct { carrier: Carrier, negotiated_version }.
   next_msg() records the daemon-acked wire version from HelloAck; new
   `negotiated_version()` accessor. The CLI already PROPOSES PROTOCOL_VERSION (2) on both
   carriers (client.rs Hello construction; nothing anywhere proposes 1 — grep verified —
   so the plan's "flip it to 2 if it proposes 1" clause found nothing to flip); the
   negotiated value is now OBSERVABLE and asserted = 2 by test against the real router.
5. Display-only ask contract verified as shipped: run.rs wait_turn answers only
   PermissionAsk from stdin; FallbackAsk/PlanAsk render and pass through unanswered
   (fallback timeout => task 9's same-model retry on the daemon side; plan approval needs
   an attached interactive frontend — tasks 19/20/21). Human lines for fallback asks and
   plan approval states were already present (task 1 sibling arms); this task pins them
   with tests (fixture-built FallbackAskPayload via serde, PlanAsk/PlanResolved direct).
