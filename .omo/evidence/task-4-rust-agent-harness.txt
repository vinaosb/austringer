DESIGN DECISIONS (binding-scope interpretation)
-----------------------------------------------
- Event taxonomy: single `Event` enum, 7 kinds (user/assistant/tool_call/
  tool_result/system/condensation/snapshot), serde internally-tagged `"type"`
  snake_case. Envelope `RecordedEvent { seq, event }` is NESTED (no
  serde(flatten) — flatten + internally-tagged enums have well-known
  lossy-buffering footguns); line = one JSON object + \n.
- LLM-visible vs INTERNAL as first-class property: `EventClass` enum +
  `EventKind::class()` (const fn) + `Event::class()/is_llm_visible()` +
  `llm_visible()` filter iterator — the sanctioned model-context path.
  Condensation + Snapshot are Internal; tested that internal kinds never
  appear in model-context serialization.
- Multimodal from turn one: `ContentBlock { Text, Image(ImageBlock) }`;
  ImageBlock = { mime: MimeType (validated image/* newtype), width, height,
  media: MediaRef { hash: ContentHash (blake3, "blake3:<64hex>" string form),
  bytes } }. Bytes live at <session>/media/<hash> (atomic temp+fsync+rename,
  exists-check dedup). NEVER inline base64 — test asserts a 4KiB image
  serializes to < 600 chars. Typed placeholder for text-only consumers:
  `ImageBlock::text_marker()` (deterministic; mime + dims + short hash).
  Vision routing deliberately absent (later todos).
- Serde stability: struct fields in declaration order (deterministic); all
  dynamic maps are serde_json Values backed by BTreeMap (sorted keys);
  preserve_order must NEVER be enabled (comment at the [workspace.dependencies]
  declaration; `object_keys_are_sorted_when_maps_serialize` test FAILS if it
  ever is). No event embeds an OS path (hashes only → cross-platform stable,
  satisfies forward-slash rule by construction). No timestamps injected.
- Writer: `EventLogWriter::append` is the ONLY mutation (no update-in-place
  API exists). Seqs 1-based monotonic via `Sequence(u64)` newtype.
  fsync policy FsyncPolicy::{Always, OnSnapshot, NeverForTests} — flush
  per event, durability barrier per policy (OnSnapshot syncs on Snapshot
  kind). Line+\n written as ONE sink write call (minimal torn window).
- Commit protocol: a line is committed iff newline-terminated. Reader:
  torn final line (no \n) => ignored + TornFinalLine anomaly, never an
  error; invalid mid-file line => InvalidLine anomaly + continue; sequence
  jump => UnexpectedSequence anomaly. LoadReport.valid_len = byte length of
  valid prefix; writer reopens at that boundary (set_len truncates any torn
  tail) so appends after a crash never merge with a partial line.
- Disk-full/IO-error contract: any append/sync failure =>
  Degradation{cause, notice} in writer state + AppendError::DegradedToReadOnly
  { cause, notice } where notice = LOUD Event::System text ("EVENT LOG
  DEGRADED — session is now READ-ONLY...") delivered through the API (never
  written to the broken file; System is LLM-visible so both user and model
  see it). Best-effort discard_partial() rollback; a surviving torn tail is
  reader-tolerated. Further appends => AppendError::ReadOnly fail-fast.
  No unwrap/expect/panic in library paths (Sequence::next returns Option;
  exhaustion is a typed error).
- Session = directory parameter: <session>/events.jsonl + <session>/media/.
  Full session store deliberately NOT built (todo 24).
- Property-test generator: hand-rolled deterministic xorshift64* with fixed
  seeds [1, 42, 0xDEADBEEF, 20260912] — ZERO new deps vs proptest (which
  pulls rand/regex-syntax/etc.), kills the flaky_tests class (no random
  seeds, no wall-clock in correctness assertions), full control over
  alphabet (CJK/emoji/control chars/quotes/backslashes) and JSON shapes.
- Deps: serde/serde_json/thiserror already in workspace graph via
  harness-test-support (no new crates to the lock). NEW: blake3 1.8.7
  (content-addressed media; CC0-1.0 OR Apache-2.0 crate; transitive
  arrayvec/cc/cfg-if/constant_time_eq all permissive & allow-listed) —
  cargo deny check green with ZERO deny.toml changes. Promoted shared
  versions into [workspace.dependencies].

RESIDUAL RISKS / NOTES
----------------------
- Writer open() scans the whole log to find the commit boundary (O(file));
  lazy/index loading is explicitly todo 24's concern.
- AppendError::Serialize is unreachable for in-construction events (no
  non-string map keys possible via serde_json::Value) but typed anyway —
  no panics in library paths.
- Single-writer assumption (no cross-process lease) — leases are todo 24.
- The loud degradation notice is a System (LLM-visible) event: the 7-kind
  taxonomy is binding and System is its runtime-notice channel; disk-full
  reaches both the user (UI) and the model (context) — "loud" by design.
