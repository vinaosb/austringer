WHAT SHIPPED
------------
1. Warp status-precedence aggregate (receipt: Warp PR#11367/#12084,
   plan draft C9 "status precedence algorithm
   InProgress>Blocked>Error>Cancelled>Success + WaitingForEvents"):
   NEW harness-daemon/src/team.rs — TeamStatus enum, child_status()
   mapping of the Child* state vocabulary (running/file_touched/
   escalation -> InProgress; blocked/collision -> Blocked; failed ->
   Error; quarantined -> Cancelled; success -> Success; unmapped ->
   InProgress, never terminal), aggregate_of_states() = max
   precedence, empty team -> WaitingForEvents. The never-flip-
   terminal-while-a-child-runs invariant is structural: InProgress
   outranks every terminal status.
2. Two NEW SessionEvent variants (events.rs):
   - TeamBudget { spawned, tokens_spent, fan_out_cap, token_budget }
     (mirrors task::DelegationSnapshot; published after each spawn
     authorization and after each spend record in run_child)
   - TeamBudgetExhausted { spent, budget } (the typed halt event,
     published when authorize() refuses TokensExhausted — alongside
     the TaskRefusal::Tokens the tool result carries, so every
     ATTACHED client sees the halt, not just the model)
3. Blocked-child ask surfacing (task/child.rs): await_child_turn now
   also selects over the child's mediation control bus; each
   PermissionAsk/FallbackAsk publishes ChildProgress{phase:"blocked",
   detail: ask summary} on the PARENT hub, each resolution publishes
   phase:"running". The control subscription is taken BEFORE the
   prompt submit (no missed-ask race). ChildProgress doc vocabulary
   extended (blocked/running).
4. TUI: transcript.rs — ChildCell gains `detail` (collision glob /
   ask summary / outcome), TeamBudgetView + SessionView::team_budget()
   + team_status() (delegates to daemon team::aggregate_of_states);
   TeamBudgetExhausted also renders a transcript Notice (visible with
   the accordion closed). render.rs team panel upgraded: aggregate
   status line + budget line + child rows with inline detail.
5. CLI: render.rs human() sibling arms for both new variants (the
   t33 lesson — exhaustive match, workspace clippy gate).
6. Web: store.js reduces child_started/child_progress/child_finished
   into state.workers (previously those frames counted as ANOMALIES —
   the only workers reducer keyed off the dead worker_claimed frames)
   and team_budget/team_budget_exhausted into state.budget +
   budgetExhausted; ui.js renders the team panel (aggregate via the
   JS port of the same precedence algorithm, budget line, exhaustion
   marker, per-child rows with detail) in the session view.
7. compat.rs: both new variants downgrade_for_v1 to Notifications
   (kinds team_budget / team_budget_exhausted, frame id preserved) —
   the t8 gate extended; team_events_tests' v1-shaped decode-ERROR
   test now covers the two new payloads too.
