RECORDED INTEROP DECISION: flacenc STREAMINFO min-blocksize normalization
-------------------------------------------------------------------------------
flacenc reports the ACTUAL minimum block size in STREAMINFO (a short final frame shrinks
it below the nominal fixed block size). The fixed-blocksize convention ffmpeg/libFLAC emit
- and the symphonia 0.6 reader enforces via strict_frame_header_check (is_fixed =
min==max, frame-numbered headers rejected otherwise) - is min == max == nominal with the
final short frame exempt. Empirically verified in an isolated scratch (outside the
workspace): symphonia decodes ffmpeg's min==max stream (8,000 samples, bs 1152, short
final block) but refuses flacenc's min<max one with IoError(UnexpectedEof) at probe, for
partial-final/single-short-block streams (exact-multiple streams pass either way).
Fix: after encode, stream.stream_info_mut().set_block_sizes(nominal, nominal) with
flacenc's own max_block_size - no frame byte is touched.
Cross-check (dev-time, ffmpeg 8.x as the independent decoder):
  ffmpeg -i normalized.flac -f md5 -        => 7bfcfe5d814a544c1521508427e7fdfd
  reference pcm_s16le input bytes md5       => 7bfcfe5d814a544c1521508427e7fdfd  (identical)
Lossless guarantee intact; documented in src/adapter/audio_flac.rs module docs.
