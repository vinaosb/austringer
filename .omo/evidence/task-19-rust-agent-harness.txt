- src/window.rs (46) - WINDOWED OUTPUT LAW: >75 lines => first 25 + last 50 +

- src/transcript.rs (53) - bounded scrollback capture: head 25 + tail 50 + count +
  lossy flag; composed() yields the bounded excerpt with overlap arithmetic
- src/screen.rs (236) - ScreenModel over vt100::Parser: slice discipline (printable
  runs bounded by wrap budget, \n/\v/\f, CSI/OSC slices with introducer handling),
  O(1) scroll capture on \n-at-bottom (confirm via new top row), wrap-byte scroll
  capture at bottom-right, full snapshot+shift-diff resync for ESC/redraw paths,
  alternate-screen capture suspension, resize, ANSI/SGR-free rendering, invalid
  UTF-8 skipped (vt100 typed skip - never a panic)
- src/spill.rs (120) - RawSpool: memory-bounded raw-stream spill; buffers to IoCap
  then streams to temp file + incremental blake3; finish => fsync + rename into the
  T6 SpillStore layout. REUSE JUSTIFICATION: SpillStore::store(&[u8]) needs the whole
  payload in RAM (a 100MB output would be a 100MB allocation), so the streaming
  writer reuses the store's directory contract + SpillStore::read recovery + IoCap
  threshold semantics, and rolls only the streaming write itself
- src/kill.rs (73) - TreeGuard: Windows Job Object KILL_ON_JOB_CLOSE assigned at
  spawn (drop = terminate tree, kernel-enforced even if WE crash); Unix
  PR_SET_PDEATHSIG(SIGKILL) + setsid fork/exec hook + killpg. Documented gaps:
  (1) microsecond assign race (todo 20 suspended-resume), (2) ShellExecuteEx
  grandchildren escape jobs (verified on this machine; todo 26 sandbox is the
  enforcement point)
- src/spawn.rs (138) - platform split: Windows portable-pty ConPTY spawn (child
  handle => job); Unix owns the fork/exec path (std Command over the openpty slave
  + pdeathsig pre_exec) because portable-pty's CommandBuilder has no pre_exec seam
- src/spec.rs (57) - ExecSpec (mandatory timeout, 120x40 default), ExecStatus
  (Completed/TimedOut/Cancelled), ExecOutcome (NO raw-bytes field - structural
  law), MAX_COMMAND_TIMEOUT ceiling 24h, typed ExecError
- src/runner.rs (239) - PtyRunner: reader thread (Pump: screen + spool + TERMINAL
  QUERY RESPONDER), waiter thread, 25ms poll loop, kill trees on timeout/cancel,
  straggler reaping on guard drop, windowed model_text + spill notice composition;
  fresh ScreenModel + fresh PTY per run (stale state structurally impossible)
- src/pending.rs (68) - PendingCommandSet: push/inspect/apply (sequential, stops at
  first non-success, remainder stays queued)/abort; CommandRunner seam shared with
  live mode
- tests: window_law (6), screen_model (15), spill_stream (4), pending_set (6),
  pty_live (10), pty_chaos (4) = 45 tests; pty_qa (4, #[ignore] evidence channels)

## Terminal query responder (key Windows finding, verified on this machine)
ConPTY/conhost sends ESC[6n (DSR cursor) and blocks the ENTIRE child until answered
(~60s timeout per query; measured: `cmd /c echo` never completing, 30s test
timeouts). Fix: the pump answers ESC[6n from the screen model's tracked cursor
(ESC[row;colR) and ESC[c with ESC[?1;2c (VT100+AVO). This is todo 20's
"DA1/DA1-query proactive injection" pathology fix, pulled into todo 19 because
NOTHING runs through ConPTY without it. Verified: identical spawn hangs without the
responder, completes in 1.5s with it (probe logs in dev notes).

## Known limitations / risks (forwarded to todo 20 + 26)
1. ConPTY read after kill: reader thread joined with a 3s grace; a still-blocked
   reader is detached (shared state is complete without it) - the full
   read-close+destroy hardening is todo 20
2. Job-assign microsecond race + ShellExecuteEx escapes (kill.rs docs) - todo 20/26
3. Scroll-region LF mid-screen with intact top row is unverifiable without a full
   diff (documented attribution limit in screen.rs; alt-screen TUIs are exact;
   spill is the lossless record)
4. Unix path (PDEATHSIG spawn, killpg) is typecheck-proven on
   x86_64-unknown-linux-gnu but NOT runtime-tested on this Windows machine - CI
   matrix (todo 3) owns the runtime proof
