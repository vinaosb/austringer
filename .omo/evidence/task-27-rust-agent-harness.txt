DESIGN DECISIONS (disclosed)
------------------------------------------------------------------------------
- Dependency direction: harness-safety stays a LEAF. The T7 chain / T8 store
  adapt onto GrantSource/AuditSink seams from core later (todo 45 wiring);
  core->safety, never safety->core, so the parallel core worker is untouched.
- Deps added: workspace `regex = "1"` + safety-deps regex/url. Both ALREADY
  in Cargo.lock via the grep-regex / mcp trees -> zero new crates compiled
  into the graph (lock diff = 2 dependency-list lines on harness-safety).
- Yolo semantics: bypass auto-approves APPROVAL asks (AskRule/FailClosed/
  ContainsRedaction->RunToCompletion) but never evaluation outcomes:
  SubstitutionGuard, CircuitBreakerTripped, ProfileClamp, ProfileCeiling
  survive. Hardline floor and hard action denies are unconditional.
- Grants consult both the absolute and root-relative target forms (T8 grant
  keys are as-extracted); grammar rules match both forms with the strictest
  verdict winning.
- Sandbox ceilings are absolute: protected paths + writable roots deny
  writes even when an allow rule matches (deny-always-wins across layers);
  reads inside roots take the ReadOnly stance without rules; secret reads
  ask (ContainsRedaction) unless an authoritative allow/grant exists, in
  which case the redaction notice rides the Allow.
- Egress: NotInEgressAllowlist is a DENY (not ask): the sandbox allowlist is
  compiled from the same rules, so divergence means the fetch cannot proceed;
  granting flows must recompile (engine exposes egress()).
- DNS-rebinding (public hostname resolving to a private IP) is documented
  out of scope for text authoring; the T26 filter proxy verifies at connect.
- execute_denies/grammar_verdict take 4-5 typed domain parameters (command/
  rules/resolver/profile etc.) - deliberate: a throwaway config struct would
  be the parameter-smuggling anti-pattern; these are independent typed
  collaborators of a cross-layer evaluation.
