## Deviations / notes

- "ParseFailure with part name" (plan QA line): the shared
  MediaError::ParseFailure is a unit variant (the M11 svg lane
  shipped the same shape for "line/col"), so the failing part name
  does not ride the error value. The refusal is typed either way;
  per-part behavior is pinned by the dedicated fixtures (missing
  document part, corrupt zip). Recorded in office/mod.rs docs.
- The executor_dispatch.rs unwired-format pin STAYS on Xlsx but its
  cited lane moved M18 -> M19: the office write lane (xlsx/docx pure
  writers) IS the next still-pending pure generate lane, so the pin's
  invariant ("always names a still-pending pure lane") holds without
  skipping over M19/M20/M21 (step generate is the freecadcmd
  subprocess; geotiff generate is the gdal subprocess).
- Binary-size canary: not re-measured for this todo - office adds no
  new dependency (zip + quick-xml already ship via the M2/M11 lanes);
  the M27 gate re-measures. No new heavy-dep rows.
- pptx extract runs PURE (zip+quick-xml) while the pptx ENTRY tier
  stays Subprocess (its generation lane is pandoc) - dispatch derives
  ProducerInfo.tier from the binding, so pptx extract artifacts
  disclose Pure (test-pinned).
- docx.rs sits at 245 code lines (warning band): the M19 write lane
