The three fixes the dead worker had diagnosed, verified on disk:

    three sibling defects (below).
(2) SSE parser test fixture semantically wrong: NOT LANDED — the
    fixture pushed 'data: {"a"' + '1}' which spells {"a"1} (colon lost

(3) socket pooling off for clean exit: LANDED (agent:false on both

Additional defects found under those three (all RED-captured before
any fix, TDD):
(a) nodehttp.openSse conflated "open settled" with "stream ended":
    settled=true was set in the 200 path BEFORE wiring res.on("end"),
    whose !settled guard could then never fire => a clean server-side
    stream close NEVER reached onEnd => the client parked forever on
    its `ended` promise (no reconnect, stop() deadlock). Isolated by
    running the attach test under node:test: connect SUCCEEDED
    ("SAW ['status','status'] opens=1") yet the test hit the 15 s
    runner timeout and the process never exited.
(b) stream.close() used request.destroy() with NO error argument =>
    Node emits no 'error' the client could observe => stop() hung
    awaiting run(). Fixed: destroy(new Error(...)) funnels through one
    finishStream() (exactly-once onError/onEnd).
(c) postJson timeout path destroyed without an error => the POST
    promise NEVER settled (the briefing's "unresolved promises"
    family). Fixed the same way; black-holed daemon now answers
    {ok:false,error:{kind:"unreachable"}} at the timeout (test drives
    it with a 200 ms transport, effect asserted, not timing).
(d) client.postCommand mapped 404 only on the network-failed branch;
    a real HTTP 404 (outcome.ok===true) became a generic http error —
    unknown_ask was unreachable. Fixed: unified status mapping
    (401/403 => auth, 404 => unknown_ask, 202 => ok). Matches the
    daemon handlers (404 "unknown ask {id}", 202 accepted).
(e) client.run(): stop() racing an in-flight openSse saw stream===null
    and closed nothing => later `await ended` hung forever. Fixed:
    after a successful open, if stopped => close the fresh stream.
(f) Dead worker's backoff test raced setImmediate retries against a
    10 ms poller (20 sleeps recorded where 3 were asserted) — the
    test was racy by construction, not the client. Rewritten with
    gate-released sleeps: the loop cannot retry until the test
    releases each backoff, so [1000,2000,4000,8000,15000,15000,15000]
    is asserted deterministically (exponential + cap proven).
(g) wrong-token test expected sseOpens===1, but auth is refused by
    the daemon middleware BEFORE routing (verified against
    harness-daemon/src/server.rs presented_token/auth_mw) =>
    sseOpens===0 is the correct effect; assertion fixed to pin "exactly
    one attempt, zero SSE handler opens".
(h) one self-inflicted test-harness leak during recovery: a polling
    helper rescheduled itself unconditionally => perpetual timer chain
    kept the event loop alive after a PASSING test (suite flakily
    failed to exit). Fixed with a done flag. Suite exit is now stable
    (EXIT=0 every run, x5).
(i) package.json "node --test test/" directory form does not resolve
    on Windows/Node 25 (MODULE_NOT_FOUND on the directory) => glob
    form "test/*.test.ts".
