DESIGN DECISIONS (for reviewers)
-------------------------------------------------------------------------------
- Signatures = keyed-blake3, NOT ed25519: zero new dependencies (task hint "justify whatever
  lands"), authentic under the self-hosted registry model (operator holds the key); the
  object-safe SignatureVerifier trait is the asymmetric seam the daemon can swap in.
- Scope choice: Scope::project/global write the SAME .harness layout at their own roots; the
  scope decision is the frontend's (todo 37/39) - the API takes the scope as a typed value.
- Secrets: install verifies RESOLVABILITY only; values are discarded after the check. Config
  files keep {{secret:NAME}} placeholders; runtime substitution belongs to the daemon's secret
  store (T29). A pack declaring a secret that cannot resolve => MissingSecret, nothing written.
- mcp_servers values are serde_json::Value passthrough BY DESIGN (declarative config patch,
  Roo 10): the registry pins and verifies their bytes but never interprets the schema; server
  names are validated; secrets inside them remain placeholders.
- The T30 skills-lock.json and this registry-lock.json are deliberately separate files with
  separate schemas: skills-lock pins whatever a directory scan finds; registry-lock records
  what the registry verified-installed.
