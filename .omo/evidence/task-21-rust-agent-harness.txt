## New dependencies (root anchors, justified)
- reflink-copy 0.1 (pure Rust): FICLONE / APFS clonefile / Windows ReFS+Dev
  Drive FSCTL_DUPLICATE_EXTENTS_TO_FILE. reflink_or_copy silently degrades to
  a plain copy PER FILE (Ok(None)=reflink, Ok(Some)=copy) — the shadow layer
  probes the first file and aborts the whole backing on any Some(_) so the
  disclosed backing is never a lie.
- gix 0.87.1 (pure Rust), default-features=false + features=["sha1"] only:
  gix-hash refuses to build without a hash feature; sha1 is pure-Rust
  (sha1_smol). No C builds added (the earlier workspace C failures — ring,
  libsqlite3-sys, tree-sitter — are all pre-existing crates). VERIFIED against
  docs.rs gix-0.87.1 + source: gitoxide has NO linked-worktree *creation*
  (feature `worktree-mutation` covers checkout/reset only), so "minimal
  worktree+odb" collapses to odb+refs: HEAD subtree materialization via
  find_tree/find_blob and reclaimed-ref writes via repo.reference.

## Implementation shape (all files <=250 pure LOC)
- src/paths.rs (52) - lexical containment validation (only Normal components:
  absolute/UNC/verbatim/../. are typed rejections) + extended-length (\\?\)
  fs shims; verbatim forms reject '/', so separators are normalized
- src/manifest.rs (76) - blake3 content manifests; symlinks and .git dirs
  skipped everywhere (never touch user's .git; shadow = working tree only)
- src/edit.rs (56) - ShadowEdit {path, expected_hash: Option, new_content}
  + batch resolution (dupes inside batch AND against already-applied edits)
- src/reflink.rs (62) - CoW tree copy with per-file fallback detection; full
  copy backing
- src/worktree.rs (152) - gix committed-tree backing: discover -> HEAD subtree
  below the target's repo-relative prefix -> materialize blobs (exec bits on
  unix); reclaimed-ref write/delete under refs/harness/reclaimed/<id>/<commit>
- src/store.rs (154) - ShadowStore, Backing{Reflink,GixWorktree,FullCopy,Empty}
  + name() disclosure, selection order reflink -> gix (only if materialized
  manifest == user manifest: dirty worktrees and smudge-filter divergence
  demote) -> full copy; forced-choice mode returns typed BackingUnavailable
- src/shadow.rs (178) - ShadowHandle: apply (validate-ALL-then-write inside
  the shadow), accessors, retire (markers + rename into reclaimed/ w/ retry,
  gix reclaimed ref); Drop = retire
- src/commit.rs (157) - the ONLY user-tree write path: full-tree drift verify
  (typed BaseDrift Modified/Deleted/Appeared/Conflict), in-memory backups,
  copy-up with full rollback on any failure (restored flag verified against
  current bytes, so a read-only file that blocked the write is not a false
  rollback-failure)
- src/gc.rs (111) - sweep(now, policy): reclaimed entries past one
  min_age-cycle deleted (refs included, bytes accounted), orphaned ACTIVE
  shadows (crashed owners) reaped by age; default 24h conservative
- Edit mapping (harness-tools, todo 16) documented in lib.rs + edit.rs:
  LineEdit batch -> apply_edits -> LineTable; ShadowEdit::replace(path,
  blake3(pre-edit bytes), table.as_bytes()); expected hash = drift contract

## QA channels
happy: 1k-file shadow create -> apply 50 edits -> commit. Windows 11 NTFS
machine => reflink unavailable (ReFS/Dev Drive absent), backing disclosed
full-copy; timings below. Instant rollback path: drop after apply leaves the
user tree byte-identical (blake3 tree digest before == after; pinned by
instant_rollback_drop_leaves_user_byte_identical + the x3 deterministic loop).
failure: reflink-unsupported -> transparent fallback (create_shadow returns a
full mirror, backing().name()="full-copy"; reflink_unsupported_falls_back_
transparently). Mid-commit failure: second of three committed files poisoned
read-only -> CommitFailed{restored:true} and the user-tree digest is
byte-identical to pre-commit (mid_commit_failure_rolls_back_fully).

## Timings (release, this NTFS machine; honest — CoW path unavailable here)
  1k files  full-copy backing : create 1246ms, apply50 33ms, discard 2ms
  1k files  gix backing       : create  865ms, apply50 34ms, discard 11ms
  10k files full-copy backing : create 13836ms, apply50 41ms, discard 15ms
The <=50ms apply+rollback budget is asserted ONLY on backing=="reflink"
(bench_apply_rollback_1k_files); on Linux/btrfs-XFS/APFS/ReFS CI that
assertion enforces the plan budget, elsewhere the number is recorded, not
faked. Observed apply+rollback on 1k/full-copy here: 35ms (within budget
anyway, but not claimed as the CoW path).

## Adversarial coverage
- malformed: traversal/absolute/\\?\C:\ UNC probes all typed-rejected w/ no
  FS writes; one bad path rejects the whole batch atomically
- stale_state: BaseDrift on modified/deleted/appeared paths (4 variants
  tested); user's own concurrent edits always survive
- cancel/resume: drop mid-transaction = instant rollback; commit is all-or-
  nothing (read-only poison test)
- hung_or_long: 1k + 10k benchmarks recorded above
- flaky x3: suite run 3x green + in-test 3-round deterministic loop
- misleading_success: blake3 tree digest asserted before/after EVERY scenario
- dirty_worktree: distinguished — dirty repo never selects gix backing
  (demoted transparently; forced gix on dirty = typed BackingUnavailable)
- new input parsing: unicode paths roundtrip; >260-char relative path
  committed and read back via \\?\ form; CRLF bytes untouched end-to-end
- symlinks: documented policy — never materialized into shadows/manifests/
  commits; edits landing on them surface as typed BaseDrift (unix test)

## Known limits (disclosed, by design)
- gix backing mirrors the COMMITTED tree; uncommitted changes are not in the
  shadow (selection self-check demotes to full-copy whenever that would
  matter for fidelity, but a clean tree plus UNTRACKED new files is also
  demoted — the manifest compare catches both). No smudge filters applied
  (CRLF-converting repos always fall back to full-copy).
- Commit materializes exactly the applied edits (no shadow-vs-user diffing,
  no deletions); rename-swap atomicity is approximated by copy-up +
  verified rollback (documented choice for Windows portability).
