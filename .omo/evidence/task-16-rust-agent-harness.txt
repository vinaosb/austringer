                 exactly once (AmbiguousAnchor typed; bare `}` needs context lines by

                 guard); atomic apply; EOL preservation (replaced range's first-line
                 ending; Eof propagation); result = changed lines + ±3 fringe, never
                 the file (new content returned to the writer only).
gate.rs          post-edit AST syntax gate via harness-ast: rejects edits that ADD
                 new error/missing nodes (count delta pre vs post), passes edits on
                 already-broken files that don't worsen them, skips unknown/uncompiled
                 languages (degrade contract).
strict.rs        ReadLedger trait + MemoryLedger (merged read windows) +
                 enforce_read_scope -> typed UnreadRegion{missing ranges} (Mentat
                 day-1 invariant: write authority scoped to read scope).
blocks.rs        indentation-anchored block reads (Roo): container-start detection,
                 upward header expansion, closer-line inclusion, tab=4 indent,
                 oversized blocks windowed w/ placeholders, blank anchor typed.
outline.rs       definitions-only mode: tree-sitter name+kind+line rows; NoGrammar
                 degrade; NonUtf8 typed.
difftokens.rs    imara-diff seam: logical-line TokenSource (CRLF-insensitive diff) +
                 postprocessed Histogram hunks.
hunks.rs         semantic staging: Histogram hunks -> entity groups; cross-entity
                 replacements split into maximal same-owner runs with new-line
                 allocation via mini Histogram alignment (equal lines follow their
                 old owner; changed regions attach to first-old-line's piece).
staged_apply.rs  y/n/e: Yes/No per entity, Expand -> per-replacement decisions
                 (finest granularity, Mentat); bounded fringes per accepted change;
                 optional syntax gate.
wip.rs           WIP-diff context: typed WipContext (files+hunks+untracked) + compact

formats.rs       edit-format routing per family (§33): OpenAI->UnifiedPatch,

                 in module docs; T34 consumes.

## Design decisions + justifications
- imara-diff 0.2 (root anchor, plan-named): git-ported Histogram, faster than Myers on
  real code, solid on pathological inputs; pure Rust; hashbrown/memchr already in tree
  (lock adds imara-diff + foldhash + a second hashbrown 0.15.5 — deny bans are
  warn-only for multiple versions). `similar` rejected (slower on kernel-scale diffs).
  harness-ast stays a crate-local path dep (NOT a workspace anchor) so the parallel
  todo-15 worker and this crate cannot collide in [workspace.dependencies].
- Uniqueness semantics: the anchor is the PAIR (line, old_text); old_text must occur
  exactly once in the file. Exact-position match wins over duplicates elsewhere;
  ambiguity only rejects during drift re-anchor or when old_text matches multiple
  locations (property-tested).
- Cross-boundary hunk splitting: contiguous replacements crossing entity lines split
  into same-owner runs; new-line allocation by a second Histogram pass inside the hunk
  (documented in hunks.rs — deterministic; rare by construction since entity headers
  are usually equal-context anchors).
- Syntax gate compares pre/post diagnostic COUNT deltas (position sets shift after
  edits); disclosed here as the documented proxy for "new errors".
- edit.rs and staged_apply.rs intentionally do NOT share an apply path: edit_lines
  enforces uniqueness anchors; staged hunks are position-authoritative (staged
  old_text is frequently non-unique, e.g. a lone `}` — reuse would wrongly reject).
- Anchor-scheme benchmark (clause 9): content-hash vs chunk-fingerprint (20-line
  chunks, offset-encoded) vs checkpoint-chain (40-line segments, xor chain, alignment
  retry). Honest recovery procedures w/ lines-read counters; #[ignore] evidence run +
  deterministic ordering tests. DEFAULT CHOSEN FROM DATA: content-hash — cheapest
  read-amplification at every recoverable shift (5/106/106 lines read vs 40/160/840
  vs ~20k), cheapest rejection at 200-line drift (19us vs 212us), CRLF-robust,
  ambiguity-safe. Chunk-fingerprint always recovers but pays whole-file scans
  (~23.6k lines); checkpoint-chain degrades quadratically with in-segment shift.

## Anchor-scheme benchmark (release, 2000-line fixture, target L1000, insert above)
scheme             shift  recovered_at  lines_read  us
content-hash           0          1000           5  32
checkpoint-chain       0          1000          40  48
chunk-fingerprint      0          1000       19620 1796
content-hash           3          1003         106  17
checkpoint-chain       3          1003         160  60
chunk-fingerprint      3          1003       19680 1728
content-hash          20          1020         106  16
checkpoint-chain      20          1020         840  127
chunk-fingerprint     20          1020       20020 1974
content-hash         200      rejected           0  19
checkpoint-chain     200      rejected           0  212
chunk-fingerprint    200          1200       23620 2473
(read-amplification model: content-hash charges its conservative full ±50 sweep on
re-anchor; chunk-fingerprint scans windows from line 1; checkpoint-chain retries one
segment per alignment shift. Insertion inside the ±2 signature window defeats
content-hash re-anchoring by design -> typed Drifted, never corrupt.)
