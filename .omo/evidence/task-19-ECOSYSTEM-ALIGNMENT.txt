Task 19 — TUI: render diffs (hunk panel), live HUD, scroll fix
==============================================================
Date: 2026-10-22
Scope: harness-tui only (+ zero harness-cli changes — no SessionEvent variants
were added, so no sibling render arms were required; t33 lesson respected).

WHAT CHANGED
------------
(a) Diffs accordion (ctrl+5): render.rs never drew view.diffs() — the README
    "hunk review gates" claim was false. New src/diffs.rs carries DiffEntry
    (path + per-hunk DiffHunk{text, HunkDecision}) with diffstat parsing;
    src/panels.rs renders one diffstat line per file (path +A/-R, N pending)
    plus every hunk line with a [pending]/[accepted]/[rejected] marker.
    y/n (while the panel is open and hunks are pending) accept/reject the
    next pending hunk in order; decisions surface as client notes.
    DECISION: accept/reject is client-side view state — the wire carries no
    hunk-decision message (ClientMsg has none; adding one would need daemon
    arms outside this task's scope). Logged in issues.md as the protocol gap.
(b) ServerMsg::Usage now feeds Hud::apply (src/app_server.rs): cache pct =
    cache_read/input_tokens*100, cost delta = cost_usd_micros/1e6, model row
    from ModelIdentity.model. HUD cache/cost/model go live; the old usage
    transcript note is gone (HUD is the surface).
(c) Dead field removed: Hud.routing_savings + HudUpdate.routing_savings +
    the "saved $X routing" cost_line suffix — no frame feeds it (Usage has
    no savings field). Screens fixture + snapshots updated accordingly.
(d) ScrollUp/ScrollDown dispatch implemented (were dead bindings): a body
    scroll offset in lines from the tail; Up clamps at compose_body length,
    Down at 0 (= auto-follow); any Event/Snapshot frame resets to 0. The
    render window keeps [end-height, end) of compose_body.
(e) Collapsed-by-default detail (Amp/Antigravity/Claude/Devin/goose 5-project
    convergence): tools accordion renders ONE line per tool (result collapsed
    to its first line, bounded at 48 chars + ellipsis) with full hunk detail
    living in the diffs accordion (expand-on-demand). Diff events carry no
    call_id, so a diff cannot be attributed to a specific tool row — diffstats
    ride the diffs panel; gap logged in issues.md.
(f) FallbackAsk and PlanAsk render as modals reusing the permission-gate
    pattern (top-of-body block, key-swallowing): fallback y = hop to proposed
    / n = keep current -> ClientMsg::FallbackAnswer{chosen}; plan y = Approve
    / n = Reject -> ClientMsg::PlanAnswer{decision}. FallbackResolved /
    PlanResolved (matching ask_id) close the modals; resolution notes remain.
    /mode plan|off (task 16) untouched.
