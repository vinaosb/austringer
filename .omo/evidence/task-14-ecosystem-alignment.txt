## What shipped
- harness-intel/src/routing/mod.rs: `Role::Explore` + `Role::Librarian` — keys "explore"/
  "librarian", class RoleClass::Utility. NO table.rs change: the existing utility-role
  cheap-pool validation (table.rs ~91-109, UtilityOffCheap) is thereby LIVE for both roles —
  wired to the existing mechanism, not duplicated.
- harness-orchestration/src/role.rs: `RoleDef::curated(name)` + `CURATED_AGENTS` + builtin()
  registration. explore = [view_window, lsp_query, search_sessions, tool_search] (search tools
  only); librarian = [view_window, search_sessions, tool_search] (docs/OSS research surface).
  Both: Tier::Explorer, CommandExecutionPolicy::Off, 1024-byte summary budget, cheap default
  bracket claude-haiku-5-5 (the routing table's cheap-pool validation owns the wire-side pin).
  Read-only by construction: no edit_lines / write / edit / execute_command / task in any
  curated allowlist (test-pinned).
- harness-daemon/src/task/readonly.rs (NEW): ReadOnlyApproval — approval-stage narrowing that
  DENIES out-of-allowlist calls BEFORE the mediated chain (structural: no permission ask, no
  executor), logs a `readonly_refusal` Notification on the child stream, and lets the loop's
  deny rendering carry the reason to the model. task_completed passes through (ReservedAware
  Approval's own carve-out).
- harness-daemon/src/engine.rs: SessionHost::readonly_stages (steer/execution identical to
  standard_stages; approval wrapped).
- harness-daemon/src/task/mod.rs: curated dispatch — `task(explore|librarian)` are RESERVED
  category names that resolve RouteRequest::Role(Role::Explore|Librarian) (cheap-pool
  validated at table build) instead of RouteRequest::Category; ChildStarted.role carries the
  curated name; `summary_budget_for(category)` clamps curated results at the agent's own
  1024-byte budget. Curated names take precedence over user categories of the same name (a
  category must not smuggle the agent onto a frontier model).
- harness-daemon/src/task/tool.rs: tool description documents the two curated agents.

## Notable implementation facts
- table.rs untouched: RoleClass::Utility on the two new Role variants makes the EXISTING
  UtilityOffCheap build gate live for them (wired, not duplicated) — the "registry rejects
  an explore declaration pinned to a non-cheap model" acceptance is RoutingTable::build /
  from_json rejecting roles[{"role":"explore","model":<frontier>}].
- Enforcement point is the APPROVAL stage (ReadOnlyApproval wrapping ReservedAwareApproval
  over the mediated chain), not the executor: a curated agent's write attempt is denied
  structurally BEFORE any permission ask can fire — refusal reason rides the loop's
  standard deny rendering to the model, and a kind=readonly_refusal Notification logs it on
  the child stream. task_completed passes through (ReservedAwareApproval's carve-out is
  preserved by delegation).
- No new SessionEvent variants (the guard logs via the existing Notification kind
  vocabulary) — the task instruction's "SessionEvent variants should NOT change here" held.
- Curated names are RESERVED task-tool vocabulary: curated dispatch takes precedence over a
  user category of the same name (test-pinned); an unrouted curated name refuses typed
  (UnconfiguredRole) rather than falling through to the category table.
- summary_budget_for(category): curated results clamp at the agent's own 1024-byte budget
  (RoleDef.curated), user categories keep the worker 2048 default.
- Sibling coordination: todo-15's edits to task/mod.rs (TeamBudget events, publish_budget,
  await_child_turn signature) landed mid-task; this task's dispatch changes were rebased on
  top of them; the curated dispatch rides inside ChildSpawn (spawn_and_run stays 3-param).
- Over-ceiling files touched surgically (flagged since todo-9/13, orchestrator-level split):
