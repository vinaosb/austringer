## 1. Scope delivered

- harness-intel: `Category` variant on `RouteRequest` (routing/mod.rs; enum drops
  `Copy` — the variant carries the user-authored category key), `categories[]`
  on `RoutingSpec` (`CategoryRouteSpec`: category + model + effort + score_floor,
  like tiers; score_floor REQUIRED like tiers), build-time validation in
  `RoutingTable::build` (unknown model, effort-grid trap, `DuplicateCategory`
  typed error), `ResolutionError::UnconfiguredCategory { category, valid }`
  (the error LISTS the valid category keys, sorted), and
  `ResolutionSource::Category(key)` (auto_routed=false — the user's config owns
  the pick, like roles).
- harness-daemon `src/task/` (new module, split under the 250-LOC ceiling):
  - `mod.rs` (233 pure LOC): `TaskServices` (routing intake + LaunchServices +
    parent-host resolver + lazily-created per-parent ledgers), `TaskRequest`,
    `TaskChildOutcome` (child host rides along for todo-15 surfacing),
    `TaskRefusal` (Depth / FanOut / Tokens / Category / ParentGone / Spawn),
    `run_child` guard chain: DepthGuard -> category resolve -> budget authorize
    -> spawn; ChildStarted/ChildFinished on the PARENT hub; token spend folded
    into the parent's aggregate after the turn.
  - `budget.rs` (73): `DelegationBudget` / `DelegationSnapshot` /
    `FanOutExceeded` + `DEFAULT_FAN_OUT_CAP=4`, `ESCALATED_FAN_OUT_CAP=
    ABSOLUTE_MAX_CHILDREN(32)`, `DEFAULT_TASK_TOKEN_BUDGET=ABSOLUTE_MAX_TOKENS
    (20M)` — the nameable per-parent aggregate todo 15 consumes (BudgetGuard
    stays per-launch; this is the explicit cross-call aggregate).
  - `child.rs` (101): bounded TurnFinished await accumulating the last
    assistant text (summary source) + Usage frames (token aggregate +
    (provider, model, effort) proof of what served); lag recovery via hub
    snapshot.
  - `tool.rs` (111): the model-facing `task` provider (category + prompt +
    escalate_fan_out), registered per-session through the task-3 registry
    pattern. Depth is checked BEFORE the parent resolves (a child invoking
    task sees fork.rs's DepthExceeded vocabulary). Success result =
    `[task child {id} category={cat}] {clamp_summary(summary, worker.summary_budget=2048)}`
    — labeled child output, marker'd clamp, never a bare truncation. Refusals
    are typed tool text; the session continues.
- SessionRouter (daemon routing.rs): per-instance dispatch request
  (`under_request(RouteRequest)` builder); task children dispatch under
  `RouteRequest::Category`, so stickiness pins per child and EVERY model change
  flows through `SessionHost::mediate_fallback` (the todo-9 ask-first
  machinery, unchanged). Unrouted-category-mid-session is a typed refusal,
  never a guess.
- CoreExecutors (tools/mod.rs): `task: OnceLock<Arc<TaskServices>>` +
  `bind_task_services`; `open_registry` registers the TaskTool when bound
  (unbound = tool absent — routing.json without categories has no task
  surface, consistent with todo 9's absent-document posture).
- bin/harness-daemon.rs: `build_state` binds TaskServices after DaemonState
  exists (parent resolver over `try_session`) and before any session opens;
  binary-size/budget note: no new dependency; perf-gate re-measurement belongs
  to the wave gate (todo-12 precedent).
- Fresh grant state: children are constructed via `SessionHost::new` +
  `standard_stages` — a fresh mediator, a fresh approval chain (fresh grant
  store), a fresh registry. Nothing session-scoped crosses the spawn boundary;
  pinned by test (below), not by convention.

## 8. Deviations / decisions recorded

- "The task-8 launch path" is reused as the CHILD-SESSION PATTERN (fresh
  SessionHost per child in the hidden namespace, executor/inference factories,
  bounded TurnFinished await, Child* events on the parent hub, parent-ledger
  cost booking) — NOT the spec-driven Launcher itself: the Launcher's resolve()
  builds models from the RoleRegistry/catalog and cannot express
  RoutingSpec-category routing, and its BudgetGuard is per-launch by design.
  The per-parent aggregate the plan demands is a different lifecycle, so it is
  its own nameable type (DelegationBudget in task/budget.rs).
- Child ids are `{parent}-child-task{ordinal}` — inside the crate's
  `-child-` namespace so `is_child_session` (journal.rs) drives depth.
- Summary clamp budget = the delegation role's (orchestration builtin
  `worker`, summary_budget 2048); categories themselves carry model + effort +
  score_floor only, per the plan's "like tiers" mandate.
- Escalation is a per-call explicit model-visible argument
  (escalate_fan_out=true) surfaced in events + refusal text — T10's "explicit
  escalation criteria" reading; the hard ceiling stays absolute.
- Token aggregate counts child Usage-frame tokens (input+output+cache) as
  reported; a lagged receiver undercounts (documented in child.rs), never
  overcounts.
- Untracked `.harness-daemon/.harness/skills-lock.json` observed in the worktree
  (created 16:23, before this task's first build at ~17:05 — pre-existing test
  leftover from a sibling task; untouched).
