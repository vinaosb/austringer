- Canonical trees: markdown = {code_blocks, code_languages, headings[{level,
  text}], lists, paragraphs, tables}; html = {census (start-tag counts,
  lowercased), doctype, text (collapsed char data, 1200-bound, truncated
  IDENTICALLY on the spec->tree side), title?}; json = the value itself, or the
  tagged {"jsonl": true, "rows": [...]} lane; csv = {bom, field_count,
  first_row|null, row_count}; toml = the JSON-normalized parse tree (datetimes
  as TOML display strings; non-finite floats as null per the M5 pinned rule).
- DIALECT CANONICALIZATION DISCOVERED (comrak): the canonical CommonMark
  formatter renders a bare fence (empty info string) as an INDENTED code block.
  The census therefore counts code BLOCKS (fenced or indented) with the
  info-first-token language key - both spellings land identically, which IS the
  dialect pinning the plan asked for (strict-CommonMark + GFM AST equivalence,
  never byte comparison). Pinned by setext-vs-ATX census equality + the
  code-fence corpus rows. Module docs disclose it.
- Markdown census definition: paragraphs count ANYWHERE in the tree (a tight
  list item's inner Paragraph included) because the spec->tree projection must
  predict exactly the AST shape the canonical writer emits; lists/tables/code
  blocks/headings counted at any depth.
- HTML5: tokenizer census (no DOM); HTML5 error recovery means a doctype-less
  fragment is a census fact, never a failure; text census joins collapsed
  character-data pieces with single spaces, and collection stops past the
  1200-char prefix (the truncation is round-trip-safe because the spec side
  truncates identically - prefix property). UTF-8 only (charset sniffing out of
  scope, disclosed). maud writer emits <!DOCTYPE html> + meta charset + lang,
  NEVER src/href/link/script (test-pinned self-contained).
- JSONL auto-detection mirrors M2's probe exactly: full single-value parse
  first, line-parse second (blank lines skipped), both failing = typed
  ParseFailure. Duplicate keys last-wins (serde_json; disclosed); canonical
  write = sorted-key compact + trailing newline (byte-pinned test).
- CSV: comma dialect only (semicolons parse as single-field rows honestly);
  ragged rows ParseFailure (flexible=false - never padded/guessed); BOM
  stripped on read + disclosed as "bom": true; writer CRLF-terminated,
  RFC-quoted, never writes a BOM (disclosed); rows counted uniformly - the
  header is a semantic convention, first_row is reported, never guessed.
- TOML: generation accepts JSON-shaped tables and refuses typed InvalidSpec
  for non-table roots, nulls anywhere, and heterogeneous arrays (recursive
  pre-validation; the serializer's own refusals map to the same error).
  Datetimes serialize as strings (JSON input cannot carry native datetimes) -
  one-way normalization, disclosed.
- Generation text contract (md/html): block text must be single-line
  whitespace-collapsed canonical text - typed InvalidSpec otherwise, never a
  silent rewrite. Code content is verbatim (multi-line ok; both census sides
  collapse identically).
- MediaError untouched (M1-frozen). QA's "invalid TOML -> ParseFailure with
  line/col" lands as the typed ParseFailure (the M1 error shape carries no
  payload - identical posture to M11's "line/col" and M13's "page hint"
  predecessors; the underlying toml error HAS line/col, we surface the typed
  refusal).
- Budgets (M1): loop lanes (comrak walk, html5gum tokens, csv records, jsonl
  lines) check deadline + cumulative-size cap EVERY iteration; one-shot parsers
  (serde_json, toml, comrak parse) bounded by input-size pre-check + post
  deadline check (disclosed per module). Structural caps: MAX_HEADINGS 4096,
  MAX_TAGS 1024, MAX_BLOCKS 10_000 (md/html), MAX_ROWS 1M (csv). Zero-deadline
  and tiny-cap tests pin both axes per lane.
- Projectors (M10 seam): Markdown/Html/Json/Csv/TomlProjector - thin wraps over
