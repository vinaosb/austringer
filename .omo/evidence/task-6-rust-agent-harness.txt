KEY DESIGN DECISIONS
--------------------
1. INVARIANT BY CONSTRUCTION: render_base_schema takes ONLY (registry, pinned) — there is no
   mode/skills parameter to vary. The core set is the CORE_TOOLS const; aux tools can never
   enter it. Aux table + pinned versions are part of the pin snapshot, so even a mid-session
   tool mount cannot churn an existing session's serialized schema.
2. PIN = CATALOG SNAPSHOT: PinnedToolSet pins tool NAMES + VERSIONS at session start. A tool
   registered later is UnknownTool to the pinned session (stale-state defense); a version
   published later is invisible to it; a fresh pin_current() sees both.
3. HYDRATION IS A TOOL RESULT: tool_search executes internally in dispatch; matched schemas
   serialize into the call's OWN observation bytes, which then flow through the SAME byte cap
   as any tool result. The system prefix (render_base_schema) is byte-identical before/after.
4. DEPRECATION = METADATA, NOT SHAPE: notices ride ToolResult.deprecation + deprecations(pinned);
   the serialized schema and the observation stay untouched (observation asserted == "ok" in
   the deprecation test).
5. SERIALIZATION STABILITY: struct fields in declaration order; parameters are serde_json Values
   (BTreeMap => sorted keys; workspace bans preserve_order); renders are pure functions —
   no timestamps, no paths, no ambient data (property-tested across twin registries).
6. task_completed is ReservedTool at the registry: the agent loop intercepts it at the
   ToolExecution operation (T5 complete_task); the registry only serializes its schema.
7. ZERO new dependencies (serde/serde_json/thiserror/blake3/async-trait/tokio already in
   workspace). cargo deny check: advisories/bans/licenses/sources all ok.
