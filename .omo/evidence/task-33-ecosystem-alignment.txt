    No model ever switched. The ask-first contract resolves strictly before the halt can refuse the next call.
    (mediation.rs untouched, read-only as required.)

==========================================================================
DESIGN DECISIONS (recorded per task instructions)
==========================================================================
- DEFAULT cap = $20/session (20_000_000 µUSD): Opus-class heavy turns (~$3-4 each) hit the 80% warning
  within ~5 turns; mid-tier sessions run dozens of turns untouched; same order of magnitude the 20M-token
  per-launch guard implies at list prices. Override is USER-GLOBAL ONLY: DaemonConfig field +
  HARNESS_SESSION_COST_CAP_USD env (binary). No repo-local surface, no new config format (extends the
  existing env seam exactly like HARNESS_PROVIDER_TIMEOUT_SECS).
- Unpriced turns: Cost::Unpriced books zero money (spend.money() == 0), token counts still carried in the
  Spend but the token dimension is uncapped in this ledger — token ceilings remain ABSOLUTE_MAX_TOKENS's
  per-launch contract. None can never trip a cap; submits are never refused on unknowns.
- Per-session halts: each SessionHost owns its ledger; other sessions keep running (structurally true —
  no shared registry; DaemonState.hosts is the registry).
- Stop semantics: CostStop is a typed terminal event; intake refusals carry the core StopReason verbatim.
  NEVER a silent drop, NEVER a model switch. Children of a stopped parent refuse at their own preflight
  (the parent ledger is their gate) — launches from a stopped session cannot spend.
- Overflow: SpendLedger record-refusals (u128 overflow) book nothing and signal nothing — core contract
  preserved; unreachable at realistic magnitudes.
- Event vocabulary on the wire: v2 clients get typed CostWarning/CostStop frames; v1 clients get
  Notification kinds cost_warning/cost_stop with the frame id preserved (t8 structural gate classified;
  compat unit test + full v1 byte-replay corpus prove no v1 breakage).

FINDING (pre-existing, out of scope, logged to issues.md)
==========================================================================
harness-core loop quirk: Operation::ALL runs Retry -> StopHook -> ExitOnError, and StopHook's consult
guard does not check last_error. On a multi-turn session (turn_ended stale-true from the previous clean
turn), a FIRST-inference failure is swallowed: StopHook returns TurnComplete and ExitOnError never runs,
so the run reports turn_complete with no failure surface. Affects ANY inference error on turns >= 2,
not only cost refusals (single-turn sessions fail typed correctly — ExitOnError's tests pass because
turn_ended starts false). Cost todo dodged it deliberately: the halt contract is proven at the provider
seam (zero calls, no assistant turns) + typed intake refusal + typed Stop event. Fix belongs in core
(guard StopHook's consult on last_error.is_none()) — flagged for the orchestrator, NOT changed here.
