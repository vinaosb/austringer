MODE DECISION (documented in acp.rs module docs): `--acp` is a
stdio-ONLY process — no HTTP/WS/IPC listener, no scheduler/IPC; the
process lives exactly as long as the IDE pipe. Sessions persist to
the same store root ({data-dir}/sessions/{acp-session-id}).

MEDIATION CONTRACT (the MUST NOT guardrails)
--------------------------------------------
- The bridge joins the session's permission queue under the
  SERVER-ASSIGNED id ACP_CLIENT_ID = "acp-stdio" — never
  client-assertable. mediator.answer()/cancel_vote() carry it, so
  the session's MediationPolicy decides whether it counts exactly
  as for a local client (FirstResponder: counts; Designated/
  LocalOnly: recorded but ignored; deadline: Timeout → Refuse).
- FallbackAsk and plan approval are NOT answerable over ACP v1:
  the bridge observes control-bus FallbackAsk frames and never
  answers; the mediation deadline (ask_timeout) resolves Timeout →
  mediate_fallback returns the CURRENT model → same-model retry per
  the task-9 dispatcher contract.
- Deny-fails-closed preserved on every unanswered shape: ACP
  option ids map allow_once→AllowOnce, allow_always→AllowSession,
  everything else (incl. unknown ids)→Deny; Cancelled outcome →
  cancel_vote → Resolution::Cancelled → Refuse; no IDE answer →
  mediator deadline → Refuse.
- session/cancel forwards into host.handle_command(Cancel) — the
  SAME queue every wire client uses. Pre-existing daemon driver
  semantics apply unchanged (deferred to the turn boundary; the
  sticky token lands on the next run) — identical to WS/SSE/IPC
  clients, never more capable.
