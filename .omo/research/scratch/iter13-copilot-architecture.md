## 1. Cloud agent execution model — VERIFIED

- **Ephemeral devcontainer-equivalent on GitHub Actions**: every session gets "its own ephemeral development environment, powered by GitHub Actions"; default Ubuntu Linux; container destroyed after completion (no persistent state). https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment
- **Environment customization** = `.github/workflows/copilot-setup-steps.yml`, must contain a **single job named `copilot-setup-steps`**, only triggers from default branch; can preinstall tools, enable Git LFS, switch to **Windows** env, upgrade to larger GitHub-hosted runners, or target self-hosted runners. Copilot code review reuses this file or a dedicated `copilot-code-review.yml`. Org owners set org-wide default runner type and can block repo override.
- **ARC runners**: self-hosted via Actions Runner Controller scale sets as `runs-on:` target (GA since 2025-10-28 changelog: https://github.blog/changelog/2025-10-28-copilot-coding-agent-now-supports-self-hosted-runners/). GitHub recommends **ephemeral single-use runners only**; requires disabling the agent's **integrated firewall** (incompatible with self-hosted + Windows); allowlist hosts incl. `api.individual|business|enterprise.githubcopilot.com`, `uploads.github.com`. https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment
- **Approval gates**: Copilot cloud-agent PRs do **not** trigger Actions workflows until a user with write access approves the workflow run (privilege-escalation guard against crafted workflow files); 2026-06-11 changelog extends the same model to `github-actions[bot]` PRs ("matches the behavior of Copilot-generated pull requests"): https://github.blog/changelog/2026-06-11-bot-created-pull-requests-can-run-workflows-if-approved/. Additional guardrails: agent can only push to **`copilot/*` branches**, cannot push to default branch or merge PRs, subject to rulesets like human developers. https://docs.github.com/en/copilot/tutorials/cloud-agent/build-guardrails (enterprise-cloud). Third-party writeup confirming isolation/branch/approval model: https://itnext.io/github-copilot-coding-agent-the-complete-architecture-behind-agentic-devops-at-enterprise-scale-1f42c1c132aa
- **Issue→PR flow**: assign issue → draft PR on `copilot/*` branch, iterates (builds, tests, lints, Playwright screenshots into PR), requests human review. Agentic code review GA'd Mar 2026 (scout fact consistent; review now has low/medium tiers + skills + MCP: https://github.blog/changelog/2026-06-02-shape-copilot-code-review-around-your-team/).

## 2. Sandboxing — VERIFIED (public preview 2026-06-02)

- **Changelog**: https://github.blog/changelog/2026-06-02-cloud-and-local-sandboxes-for-github-copilot-now-in-public-preview/ — `/sandbox enable` in any session; local sandboxing on **Microsoft MXC** (Microsoft eXecution Container) for consistent isolation across macOS/Linux/Windows; **Intune + other MDM** can centrally configure/enforce local sandbox policies; local = included in Copilot seat; cloud = usage-billed.
- **Local (MXC)**: CLI declares policy (readable/writable paths, network on/off); MXC applies via per-OS backends — macOS **Seatbelt**, Linux **bubblewrap**, Windows **ProcessContainer** (AppContainer); "lighter-weight end of spectrum", NOT a VM/container. Docs: https://docs.github.com/en/copilot/concepts/about-cloud-and-local-sandboxes. MXC repo: https://github.com/microsoft/mxc/ (Rust, JSON schema, TS SDK, backends: processcontainer, windows_sandbox, wslc, microvm/nanvix, hyperlight, isolation_session; **"no MXC profiles should be treated as security boundaries currently"** per repo warning). Windows/Agent 365 context: https://blogs.windows.com/windowsdeveloper/2026/06/02/windows-platform-security-for-ai-agents/
- **Cloud**: `copilot --cloud` runs the whole CLI session in "fully isolated, ephemeral Linux environments hosted by GitHub", built on **Azure Container Apps Sandboxes**; experimental flag required (`--experimental`); interactive-only (no `-p`/`-i`); inherits existing cloud-agent policies (firewall etc.) with zero extra setup; sessions resumable from another machine. Docs: https://docs.github.com/en/copilot/concepts/about-cloud-and-local-sandboxes
- **Bundle forensics** (local CLI 1.0.83): `app.js` contains `mxc`×7, `seatbelt`×8, `bubblewrap`×2 strings → MXC policy generation is live in the shipped runtime.
- **Enforcement**: Intune/MDM policy application confirmed in changelog + VentureBeat (Defender/Entra/Intune/Purview via Agent 365, preview July 2026): https://venturebeat.com/security/microsoft-launches-mxc-an-os-level-sandbox-for-ai-agents-with-openai-and-nvidia-already-on-board. InfoWorld hands-on (default lockdown to PATH/cwd/temp/profile, outbound-only net): https://www.infoworld.com/article/4215416/running-ai-agents-in-sandboxes-with-microsoft-execution-containers.html
- CLI changelog: "Unconditional autopilot approval now disables sandbox for the current session when bypass is allowed" → sandbox integrates with permission engine.

## 3. CLI architecture — VERIFIED (GA 2026-02-25)

- **GA changelog**: https://github.blog/changelog/2026-02-25-github-copilot-cli-is-now-generally-available/ — "full agentic development environment"; README (repo SHA above): "Powered by the **same agentic harness** as GitHub's Copilot coding agent" → one engine across CLI/IDE/cloud/app.
- **Agent loop** (SDK doc, authoritative): SDK is a JSON-RPC transport; CLI runs the tool-use loop; "Each iteration … is exactly one LLM API call, visible as one `assistant.turn_start`/`turn_end` pair… There are no hidden calls." Completion signals: `session.idle` (always, mechanical) vs `session.task_complete` (semantic, persisted). **Autopilot**: CLI injects a synthetic user nudge when loop ends without `task_complete` (two-level completion). Events log at `~/.copilot/session-state/<sessionId>/events.jsonl`. https://github.com/github/copilot-sdk/blob/main/docs/features/agent-loop.md
- **Built-in agents** (docs): `explore` (read-only, code intelligence+grep+glob+view+shell, parallel-safe), `task` (runs tests/builds/linters, brief summary on success/full output on failure), `general-purpose`, `code-review` (high signal-to-noise, no edits), `research` (only via `/research`), `rubber-duck` (critic on a *different model*), plus **plan mode** and **autopilot** as modes, and the **`/fleet` orchestrator**. https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents
- **`/fleet`** (2026-04-01 blog): orchestrator decomposes → dependency graph → dispatches parallel background subagents (own context windows, **shared filesystem, no file locking — last-writer-wins**) → polls → verifies → synthesizes; custom `.github/agents/` agents selectable per track. https://github.blog/ai-and-ml/github-copilot/run-multiple-agents-at-once-with-fleet-in-copilot-cli/
- **plan.md**: agent planning state persisted at `~/.copilot/session-state/{sessionId}/plan.md` (SDK session-persistence doc). Plan mode "hard-blocks built-in tool calls that would modify the workspace" (repo changelog). `/plan` + `--mode autopilot` + `--plan` chaining supported.
- **Session persistence**: `~/.copilot/session-state/{sessionId}/` containing `checkpoints/001.json…` (turn snapshots), `plan.md`, `files/` (artifacts), `events.jsonl`. API keys are **never persisted** (BYOK must be re-supplied on resume). Resume options: model, system prompt, tools, reasoning effort, workingDir, MCP servers, agents, skills, infiniteSessions. https://github.com/github/copilot-sdk/blob/main/docs/features/session-persistence.md
- **Infinite sessions**: auto-compaction at **95%** of context (CLI GA changelog: "compresses history in the background… virtually infinite sessions"); SDK exposes `backgroundCompactionThreshold: 0.80` / `bufferExhaustionThreshold: 0.95`; manual `/compact`; `/context` shows token breakdown. OTel spans carry `gen_ai.conversation.compacted=true` + CompactionPart.
- **Hooks**: `.github/hooks/*.json` (repo) + `~/.copilot/hooks/*.json` (personal); events `sessionStart`, `sessionEnd`, `userPromptSubmitted`, `preToolUse` (can deny/modify; exit code 2 = deny), `postToolUse`, `agentStop`, `subagentStop`; command type bash/powershell, timeout default 30s, synchronous+blocking. https://docs.github.com/en/enterprise-cloud@latest/copilot/concepts/agents/hooks
- **Distribution/forensics (local)**: npm `@github/copilot` → `copilot.exe` **138 MB** (bundled Node runtime/SEA) + `runtime.node` **79 MB** native module + **17 tree-sitter WASM grammars** (bash, c, cpp, csharp, css, go, html, java, js, json, php, python, ruby, rust, scala, ts, tsx) + `tgrep.exe` (tree-sitter structural grep) + `ripgrep` + `CopilotComputerUse.exe` (computer-use plugin). `pty`×319 in bundle → native PTY shell execution. Requires PowerShell v6+ on Windows (README).
