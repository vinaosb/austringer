## 2. Antigravity 2.0 desktop app architecture

- **Projects primitive** (new in 2.0): a project bundles settings + resources + permissions for all agents inside it; multi-folder access (cross-repo context); per-project permission overrides on top of global; "standalone" conversations run in an isolated scratch folder. https://antigravity.google/docs/projects/ , https://www.antigravity.google/docs/features?app=antigravity , https://antigravity.google/blog/google-io-2026-feature-deep-dive
- **Async agents**: long ops (npm install etc.) offloaded to background processes so the main loop/UI never blocks; background task "sets up an intercepting message client to catch and stream subagent responses back to the main agent's progress log in real-time… loops and polls the subagent states periodically." Scheduled Tasks = cron sidecars launching agents autonomously. https://antigravity.google/blog/google-io-2026-feature-deep-dive , https://antigravity.google/docs/sidecars/
- **Git worktrees native**: "New Worktree Mode" provisions a worktree in background; when a main agent fans out isolating subagents it "autonomously creates the worktrees for those conversations and handles cleanup automatically." (same IO blog)
- **Subagents**: parent calls `invoke_subagent` → concurrent session with role+prompt. Workspace modes `inherit` / `branch` (isolated Git worktree) / `share`. **Context isolation**: subagent starts clean, does NOT inherit parent conversation history. Built-ins: `research`, `browser` (/browser only), `self` (clone). Custom subagents = Markdown + YAML frontmatter (`name`, `description`, `tools[]`, `mainAgent`, `subagent`, `model: inherit|flash|pro`, `commandExecutionPolicy: off|auto|eager|sandbox`, `mcpServers[]`, `skills[]`); or transient via `define_subagent` tool. Three lifecycle states; cancel via panel / `k` in CLI. **Permission bubbling**: subagent approval requests bubble to main UI; subagents inherit parent's allowed command prefixes, file scopes, sandbox settings. https://antigravity.google/docs/subagents/
- **Monitoring UI**: subagent panel; `Alt+J` jumps to subagent awaiting approval (desktop & CLI); CLI `/agents` panel shows live checklist (active/completed/killed/failed) with full reasoning-log Detail View; `/tasks` for plain background shells; `Ctrl+K` fast-path approval. https://www.antigravity.google/docs/cli/subagents/
- **Hooks**: JSON, global + workspace (workspace wins), lifecycle points: before/after tool execution (mutate args / log), before/after model call (inject instructions / override exit rules), agent-loop stop conditions (force checks / block termination). https://antigravity.google/docs/hooks/ , IO deep-dive.
- **Agent Teams panel**: task's "Agent Teams panel" = the UI subagent panel + Teamwork monitoring ("monitor live progress across agent tracks in the UI subagent panel or CLI status bar", `Alt+J`). https://antigravity.google/docs/teamwork/

## 5. Teamwork, /boost, A2A

Verification = "adversarial falsification and independent success audit." Infra: **per-agent scratch directories** (scripts/notes/logs out of project root); structured state + artifact handoffs (every state change, command, review comment, verification log recorded into plan/progress artifacts + conversation logs). Horizon "hours to days." Comparison table (boost doc): Teamwork = persistent isolated worktrees per milestone; `/boost` = ephemeral isolated worktrees.

## 8. Trust model

- **Unified permission engine**: every sensitive op is `action(target)`; three lists evaluated **Deny > Ask > Allow**. Actions: `read_file`, `write_file` (implies read), `read_url`, `execute_url`, `command` (word-by-word prefix + `regex:`), `unsandboxed`, `mcp`. Interactive prompts allow editing the grant scope in-place (not for terminal commands). Defaults: workspace files auto-allowed; everything else (commands, MCP, web read/actuation, non-workspace files) → **Ask**. https://antigravity.google/docs/permissions/
- **Autonomy tiers**: task said "4 autonomy modes" — the documented 4-value ladder is subagent `commandExecutionPolicy: off | auto | eager | sandbox` (https://antigravity.google/docs/subagents/); user-facing terminal policy is 3-way **Request Review / Proceed in Sandbox / Always Proceed** + sandbox on/off toggle + **Security Presets** Default (Require Review, files Always-Ask) / Full machine / Turbo (Always Proceed) / Custom (https://antigravity.google/docs/sandbox/ , https://antigravity.google/docs/agent-settings/).
- **Terminal-execution policy** = above. **JS/browser-execution policy**: no standalone "JS execution" setting found in 2.0 docs — browser actuation is governed by `execute_url` Ask-default + browser allowlist/denylist; treat scout's "JS-execution policy" as **UNVERIFIED (IDE-era naming)**.
- **Terminal Sandbox (Preview)**: native OS isolation — "**Linux namespaces and macOS `sandbox-exec`**" (https://antigravity.google/docs/agent-settings/); project+temp+build-cache mounts read-write, allowed read paths read-only, everything else invisible; `~/.ssh`/`.env` blocked; network limited to `read_url`-granted domains compiled into container `AllowedDomains`; `unsandboxed(...)` escape rules; per-project override. Windows support **not documented** (docs name Linux/macOS mechanics only).
- **Encryption at rest** (3rd-party verified): conversation transcripts stored as encrypted `.pb` under `~/.gemini/antigravity/conversations/` using **Electron `safeStorage`** (macOS Keychain / Windows DPAPI / Linux Secret Service; hardware-bound key resisted Frida extraction) — https://ericxliu.me/posts/reverse-engineering-antigravity-ide/ . Counter-evidence: MCP OAuth tokens sit in plain JSON `mcp_oauth_tokens.json` per official docs (https://antigravity.google/docs/mcp/). Net: ◐.
