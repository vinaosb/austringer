## 1. VM-per-agent execution model (Brain/Devbox split)

**Canonical architecture (docs mirror, enterprise deployment overview):** Devin = **Brain** (stateless inference/planning service, *always* in Cognition's cloud) + **Devbox** (dedicated execution VM: shell, browser, code editor). "Each Devin session runs on its own isolated machine." Devbox opens a **secure WebSocket** to an isolated container in Cognition's tenant on startup; all ops flow over that channel.
- URL: https://cognitionai.mintlify.app/enterprise/vpc/overview (mirror of https://docs.devin.ai/enterprise/deployment/overview)
- Session tools (human-side monitor/takeover): **Shell** (read-only→writable toggle, command history), **IDE** (live VSCode on Devin's machine), **Desktop** tab (renamed from "Browser" — full interactive desktop environment, not just browser), **Progress** tab. https://docs.devin.ai/work-with-devin/devin-session-tools
- Session UI served via iframes from `*.devinapps.com` (enterprise proxy allowlist requirement).

**Deployment split:**
| Model | Brain | Devbox | Notes |
|---|---|---|---|
| Enterprise Cloud (default, multi-tenant) | Cognition cloud | Cognition cloud | IP allowlist / public resources |
| Customer Dedicated Deployment ("Dedicated Tenant") | Cognition cloud | single-tenant customer-isolated VPC | AWS PrivateLink or IPSec; MFA-VPN compatible; OpenVPN supported |
| Enterprise Assured | Cognition cloud | dedicated + **Customer Managed Keys (AWS KMS)** | https://docs.devin.ai/enterprise/security-access/security/customer-managed-keys |
| **Devin Outposts** (2026-07-21) | Cognition cloud (inference/planning stay put) | **customer-operated machines** | see below |
| Devin Local | Cognition cloud | user's local machine (inside Devin Desktop) | see below |

**Devin's machine internals:** VM **snapshot loaded at session start** = "Devin's Workspace" (repos + toolchain preinstalled; direnv preinstalled; bash; `~/.bashrc`; machine size disk/RAM/CPU configurable in Settings > Workspace > Danger Zone). Blueprint system: Devin can generate a blueprint from a repo; reviewed blueprints build snapshots (https://docs.devin.ai/onboard-devin/environment/blueprints.md). Browser: Chrome with **CDP endpoint at localhost:29229** for Playwright scripted auth flows; cookies persist in environment/browser profile (https://docs.devin.ai/work-with-devin/browser-auth).
**Computer Use:** full desktop (mouse/keyboard/screenshot-action loop, 1024×768 perceived display), Linux default; **Windows sessions** (WPF/WinForms testing, Windows blueprints, ~**9% more ACU** than Linux); **macOS only via Outposts** (Namespace Devboxes, Apple M5; TCC Screen Recording + Accessibility permissions). https://docs.devin.ai/work-with-devin/computer-use ; https://docs.devin.ai/onboard-devin/environment/windows-support

**Devin Outposts (verified, 2026-07-21):** NOT self-hosting the whole product — agent loop stays in Devin Cloud; **command execution, file edits, repo access happen on customer machines**. Mechanics: named queues ("Outposts"); session enters queue → claimed by a **self-hosted worker** (`devin-remote`, worker image `public.ecr.aws/e0h8a4b6/devin-cli:stable`); claims expire on server deadline → session **self-heals back into the queue** (reconciliation loop). Open-source K8s operator **devin-outpost-k8s (Rust, MIT)**. Partner deployment templates: Cloudflare (edge sandboxes + proxies), Daytona, E2B, Modal (GPU, scale-to-zero), Namespace (macOS M5 devboxes), NVIDIA Brev/OpenShell (GPU sandboxing). Opt-in; off by default on Dedicated Tenant. Select outpost via Configuration → Virtual environment or Slack `!outpost` bang.
- Blog: https://devin.ai/blog/introducing-devin-outposts
- Docs: https://docs.devin.ai/cloud/outposts/overview , /quickstart , /orchestration , /reference , /partners
- Corroboration: https://blog.kubesimplify.com/devin-outposts-on-kubernetes ; https://logicoflogic.com/news/cognition-devin-outposts

**Devin Local:** local agent inside **Devin Desktop** (the IDE product formerly branded Windsurf; rename ~2026-06-02 with Local as default local agent, per https://www.digitalapplied.com/blog/windsurf-becomes-devin-desktop-ide-migration-2026). Direct local machine access (shell, env vars, local DBs) vs cloud VM. Enterprise "Local Agent Controls" page governs Desktop+CLI: https://docs.devin.ai/enterprise/local/controls ; CLI self-described as "a local agent like Cascade": https://docs.devin.ai/cli/enterprise/controls. Local execution details thin in docs — **UNVERIFIED:** whether Local uses the same Brain loop or a local harness loop.

**Windows / Git Bash:** CLI runs on Windows; **OS sandbox unsupported on Windows** (hard-fail with `--sandbox` or Required enforcement, incl. ACP-in-Desktop); Linux sandbox = bubblewrap(`bwrap`)+socat, fail-closed. Terminals: Git Bash = "Supported (some features limited)" tier; Windows Terminal 1.25+ recommended; cmd.exe conhost unsupported. https://docs.devin.ai/cli/sandbox ; https://docs.devin.ai/cli/reference/terminal-compatibility

## 2. Fusion harness internals (multi-model)

Two-phase rollout:
1. **Cloud preview (2026-06-29):** hybrid harness around (a) **"sidekick" agent** — smaller cheaper model runs *in parallel* with frontier agent; frontier agent delegates, monitors, keeps planning/ambiguity/final review; each agent keeps **own tools + own cached context** (avoids naive-routing cache misses); (b) **dynamic mid-session routing** — model switch happens *at compaction events* ("model switching for free", can even swap sidekick→other cheap model with **no extra cache penalty**). Claims: up to **60% cheaper** at frontier quality (Opus/GPT-5.5-class leads), 41% w/ Fable 5; benchmark = own **FrontierCode 1.1** (updated 8/7/2026). https://cognition.com/blog/devin-fusion
2. **Local Fusion in Devin Desktop + CLI (later):** you explicitly pick **lead** (planning/review) + **sidekick** (execution) + **effort**; recommended pairing **Fable 5.1 + SWE-2**; up to 39% more efficient; independently evaluated with **Artificial Analysis + Vals AI**. `/fusion` picker; `/model` to leave; **Fast Mode** = faster model variants at higher cost; paid plans only (CLI ≥3000.10.20, Desktop ≥3.10.0). https://cognition.com/blog/local-fusion ; https://docs.devin.ai/cli/fusion
- **Pair-specific harness policies:** brief specificity, autonomy, review depth tuned per lead/sidekick pair; "pricier sidekicks can lower total session cost via fewer retries." (https://alphasignal.ai/news/cognition-s-fusion-cuts-devin-coding-agent-costs-by-46-with-two-model-teamwork)
- **Cost HUD:** `/session-stats` shows token usage, cost by model, **estimated Fusion savings**. https://docs.devin.ai/cli/fusion
- Other routing: **Adaptive** router (auto model selection) https://docs.devin.ai/cli/adaptive ; Slack bangs `!ultra !fast !lite !fusion !swe !normal` (https://docs.devin.ai/get-started/first-run); agent types Devin / Fast Mode / **Dana** (data analyst) mid-session switchable.
- Model serving (from SWE-2 post): NVFP4/FP8 kernels + quantization-aware training, SpecForge draft model (+15% accept length), prefill delayer (+10-20% TPM/tokens-per-sec) — https://cognition.com/blog/swe-2

## 5. Sessions, snapshots, metering

- **Sessions:** persistent, resumable, sleep after **30 min idle (default, enterprise-tunable 5-120 min)**, no usage while sleeping; wake by message; **no concurrent session limits**; shareable; full lifecycle via API v1/v2/v3 + MCP + Terraform. https://docs.devin.ai/admin/billing/usage
- **ACU metering (internal unit):** usage = *number/complexity of actions* (planning, context gathering, browser, code exec) + *VM time & bandwidth* (small fraction); **Windows sessions ≈ +9%**; no charge while waiting on user/tests/setup-clone. Enterprise ACU pool w/ org + per-user caps (usage policies, IdP-group tiers); self-serve = quota then on-demand credits. Per-session usage visible in Session Insights. Consumption APIs (v2/v3 daily by session/user/service-user/org). https://docs.devin.ai/admin/billing/usage ; /enterprise/features/usage-policies
- **Scout's "session sizes ACU-only"**: consistent — platform exposes ACU/action counts, not token-window sizes; token-level detail appears only in CLI `/session-stats`. **Snapshots:** environment blueprints → build → snapshot; workspace resets to saved machine state each session; manual "create snapshot" workflow; browser-profile snapshot (browser-auth). **Replay:** command history time-travel in session UI (2024 notes); `devin_session_events` MCP tool (event summaries/full details/search); Session Insights analytics. No per-edit undo/rewind documented.
