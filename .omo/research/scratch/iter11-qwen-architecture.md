## 1. Architecture narrative

### 1.1 Two execution models, one agent core

Qwen Code is an npm-workspaces TypeScript monorepo ([architecture](https://qwenlm.github.io/qwen-code-docs/en/developers/architecture/)). The agent loop lives exclusively in `packages/core` ("UI-independent agent orchestration, model-provider integration, prompt and context construction, tool registration and execution, permissions, sessions, memory, telemetry"); all presentation/transport lives in adapters. Two execution models:

- **Direct execution:** the Ink-based interactive TUI or headless CLI constructs the core runtime in-process. Flow: CLI parses args → resolves config (args/env/user/workspace settings) → optionally enters sandbox → core builds model request → agent/tool loop → tool calls checked against permission policy → executed in workspace → incremental events rendered or serialized.
- **ACP execution:** `qwen --acp` hosts the same core behind the **Agent Client Protocol** (JSON-RPC/NDJSON over stdio). This child is the unit of agent execution everywhere else.

### 1.2 Daemon / event bus (`qwen serve`)

`qwen serve` wraps ACP execution in an HTTP + SSE control plane ([daemon 00-index](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/00-index/), [01-architecture](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/01-architecture/)). Topology:

```
clients (TUI-adapter, Web Shell, VS Code, channel bots, SDK) 
  → Express HTTP edge (origin-strip → log → trace-id → host-allowlist → CORS → bearer → rate-limit → JSON → telemetry → mutationGate)
  → AcpBridge (packages/acp-bridge) 
  → ACP child `qwen --acp` (agent runtime + McpTransportPool + WorkspaceMcpBudget)
```

- **Workspace scoping:** one primary workspace by default; with `multi_workspace_sessions` each registered workspace owns its own bridge + ACP child pair. `sessionScope: 'single'` (default) multiplexes *all* clients onto one shared ACP session; `'thread'` mints per-conversation sessions ([08-session-lifecycle](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/08-session-lifecycle/)).
- **Event bus:** per-session `EventBus` ([10-event-bus](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/10-event-bus/)) assigns monotonic ids (from 1), buffers in a bounded replay ring (default **8000**, soft cap 1M), fans out to ≤64 subscribers with per-subscriber caps (256 frames / 2 MiB). Slow clients warn at 75% fill (37.5% hysteresis) via `slow_client_warning`; overflow evicts with a terminal id-less `client_evicted`. `Last-Event-ID` resume replays from the ring; if the cursor predates ring head, the bus emits `state_resync_required` (id-less, recovery-oriented) and the SDK reducer auto-skips deltas until a snapshot reload — a divergence-proof resync design. 53 typed event kinds at `EVENT_SCHEMA_VERSION=1` ([09-event-schema](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/09-event-schema/)).
- **Auth/security** ([12-auth-security](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/12-auth-security/)): token-less loopback = trusted local operator; non-loopback binds *fail closed* without a bearer (constant-time compare); `--require-auth` extends bearer to loopback; host allowlist vs DNS rebinding; default-CORS-deny; mutation gate; `/health` exemption; device flow; optional TLS (BYO cert); secret-bearing QR code for LAN pairing of the phone Web Shell ([qwen-serve](https://qwenlm.github.io/qwen-code-docs/en/users/qwen-serve/)).
- **Lifecycle:** two-phase graceful shutdown (10s child close deadline, 5s HTTP force-close, second SIGTERM = `killAllSync()+exit(1)` orphan prevention); disconnect-reaper guard defers reaping when other clients are attached (`spawnOwnerWantedKill`).

### 1.3 Session model

- **Identity:** `X-Qwen-Client-Id` (self-reported, charset/length-validated) identifies each attached client; `attachCount` + `clientIds` map track multiplicity; `originatorClientId` stamps attribution and drives the `designated` permission policy. Sessions support create/attach/load/resume, heartbeat, metadata (`displayName` ≤256), non-blocking prompt (HTTP 202 + `promptId` correlation), side-queries `recap` (one-line "where did I leave off" via fast model) and `btw` (single-turn forked question that never mutates main history) — the latter explicitly runs `runForkedAgent` on the **cache path** ([08](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/08-session-lifecycle/)).
- **Persistence & recovery:** conversation transcripts page out via `GET /session/:id/transcript`; multi-daemon concurrent access is governed by **writer leases** with fail-closed recovery (no force-unlock API; boot-id/PID-namespace identity checks; certified sealed handoff requires valid transcript proof) ([conversations-recovery](https://qwenlm.github.io/qwen-code-docs/en/users/conversations-recovery/)). A PID-keyed **session registry** (`$QWEN_HOME/sessions/<pid>.json`, 0700 dir/0600 file, `procStart` boot-id+start-ticks anti-PID-reuse, per-PID-namespace scoping) makes live sessions discoverable to external processes ([cross-session-protocol](https://qwenlm.github.io/qwen-code-docs/en/users/features/cross-session-protocol/)).

### 1.4 Context engine

- **QWEN.md hierarchy:** `~/.qwen/QWEN.md` (user) → project `QWEN.md` (+ reads `AGENTS.md` if present) → `.qwen/QWEN.local.md` (personal overlay); `@file` imports; `/init` bootstraps it ([memory](https://qwenlm.github.io/qwen-code-docs/en/users/features/memory/)).
- **Auto-memory:** background extraction after conversations of four categories (about-you / feedback / project context / external refs) into per-project markdown at `~/.qwen/projects/<project>/memory/` (per-worktree isolation, branch-shared). `pinned/` subdirectory is protected from extraction and from forked "Dream" consolidation workers (deterministic tool gate incl. symlink resolution). **`/dream`** = periodic dedup/consolidation (daily background, manual trigger). **Team memory** (opt-in) shares a third tier via git at `.qwen/team-memory/` with credential scanning on write.
- **Compression:** `/compress` (alias `/summarize`) replaces chat history with a summary — destructive; implemented by `chatCompressionService` ([code](https://github.com/QwenLM/qwen-code/blob/28df8b8a7897b0a8490220d00280c1c17d5ad002/packages/core/src/services/chatCompressionService.ts)). Contextual tips proactively suggest `/compress` at 50–80% context and urge it ≥95% ([tips](https://qwenlm.github.io/qwen-code-docs/en/users/features/tips/)). **Auto-compress threshold:** UNVERIFIED (no doc found; tips are advisory only).
- **Prefix-cache discipline is a first-class design constraint:** forks deliberately inherit the parent's *exact* system prompt + tool declarations so the DashScope prompt cache prefix is shared ("saving 80%+ token costs" with 3 parallel forks); `fork_tools` restrictions narrow *execution* without changing model-visible declarations, preserving the cached prefix ([sub-agents](https://qwenlm.github.io/qwen-code-docs/en/users/features/sub-agents/)); `btw` also runs on the cache path. `/stats` surfaces cached-token savings (API-key auth only; OAuth excluded) ([token-caching](https://qwenlm.github.io/qwen-code-docs/en/users/features/token-caching/)).

### 1.5 Tools & edit formats

Built-in tool registry in `packages/core/src/tools` (verified by directory listing): file ops (`read_file` w/ `offset`/`limit` windowing, `write_file`, `edit`, `notebook-edit`, `read_many_files`, `glob`, `grep`+`ripGrep`, `ls`), `shell`/`exec`, web (`web_fetch`, `web_search` w/ DashScope backend), planning (`enter/exit_plan_mode`, `todo_write`), memory, `skill`, agents (`agent`/`list_agents`/`send_message`, `team_create/delete`, `create_sub_session`), scheduling (`cron_create/list/delete`), worktrees (`enter_worktree`/`exit_worktree`), `monitor`, `lsp`, `image_gen`, `display_image`, `zoom_image`, `tool_search`, `code_mode`, `ask_user_question`, `structured_output`, `record_artifact/source`, `report_findings`, `loop_wakeup`, `request_shutdown`.

- **Edit format:** string-replacement edit rendered as diffs (`createPatchSmart`, `getDiffStat` in `diffOptions.ts`), gated by **prior-read enforcement** — an edit is rejected unless the target was previously read (`priorReadEnforcement.ts`), plus grep/read tracking. Permissions interplay: `file-read-permission.ts`.
- **Shell execution runs under a real PTY**: `@lydell/node-pty` (all 4 platform triples) + `conpty-host.ts` on Windows + `web-terminal-registry` for browser terminals ([core package.json](https://github.com/QwenLM/qwen-code/blob/28df8b8a7897b0a8490220d00280c1c17d5ad002/packages/core/package.json#L146-L151)). Read-only shell detection uses a **tree-sitter shell AST** (`shellAstParser.ts`) — the repo's only AST machinery (no repo-level code map).

### 1.6 Sandbox mechanics

[users/features/sandbox](https://qwenlm.github.io/qwen-code-docs/en/users/features/sandbox/): two providers — **macOS Seatbelt** (`sandbox-exec`; profiles `permissive-open` default / `permissive-closed` / `permissive-proxied` / `restrictive-open|closed|proxied`; custom profiles via `.qwen/sandbox-macos-<name>.sb`) and **Docker/Podman containers** (published image `ghcr.io/qwenlm/qwen-code:<ver>`, workspace + `~/.qwen` mounted, `SANDBOX_FLAGS` injection, `--sandbox-image` override). Windows/Linux = containers only. Precedence: `QWEN_SANDBOX` env > `-s` flag > `tools.sandbox` setting. The daemon additionally has a **`WorkspaceFileSystem`** path-policy/audit seam (`packages/cli/src/serve/fs/`, `assertTrustedForIntent`, ignore-aware) shared by daemon and adapters ([07-workspace-filesystem](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/07-workspace-filesystem/)).

### 1.7 Extension surface

Five layers ([architecture](https://qwenlm.github.io/qwen-code-docs/en/developers/architecture/)): **MCP servers** (tools/prompts/resources; stdio/SSE/streamable-HTTP; OAuth token cache plaintext by default, opt-in keychain/AES-256-GCM via `QWEN_CODE_FORCE_ENCRYPTED_FILE_STORAGE=true` [mcp-server doc](https://qwenlm.github.io/qwen-code-docs/en/developers/tools/mcp-server/)); **extensions & skills** (extensions bundle commands/agents/skills/MCP config per `qwen-extension.json`; skills = `SKILL.md` folders, personal/project/extension scopes, `paths:` glob gating, `priority`, `user-invocable:false` [skills](https://qwenlm.github.io/qwen-code-docs/en/users/features/skills/)); **hooks** with 4 executor types — `command`, `http`, `function`, and **`prompt` (LLM-evaluated hook)** — at PreToolUse-style lifecycle points [hooks](https://qwenlm.github.io/qwen-code-docs/en/users/features/hooks/); **channel plugins** (extension-defined adapters); **SDK clients** (TS `query()` + DaemonClient; Python/Java alpha). **No WASM plugin API exists** — wasm references in the tree are incidental (node-repl Jupyter kernels, shiki stub, Cargo locks). **No MCP-server mode** (qwen acting as an MCP server): UNVERIFIED/absent — the project exposes ACP (`qwen --acp`) and HTTP/SSE instead.

### 1.8 Subagents, teams, Arena

- **Subagents:** markdown-defined (`.qwen/agents/` project > `~/.qwen/agents/` user > extension-provided), YAML frontmatter: `model` (`inherit` | `fast` | modelId | `authType:modelId` cross-provider), `approvalMode`, `tools`/`disallowedTools`. Background by default with a **20-slot notification queue** with priority-aware eviction (agent/workflow results and scheduled prompts never evicted; monitor pulses evicted first; discards reported, never silent). `list_agents` + `send_message` continue completed/paused agents (resident runtime reuse or transcript revival). `working_dir` pins a subagent to an existing git worktree.
- **Fork subagent** (`subagent_type:"fork"`): inherits parent's full conversation (`fork_turns` to bound), exact parent system prompt + declarations (cache sharing), detached execution, `fork_tools` execution-narrowing incl. `mcp__server__*` patterns, named restriction profiles in `.qwen/fork-profiles/<name>.md`; recursive delegation blocked at runtime; never executes `ask_user_question`; **no worktree isolation** (known limitation).
- **Agent Team** (experimental, `experimental.agentTeam`): `/coordinate` — leader + up to 3 teammates, shared task list, peer-to-peer messaging, enforced read-only workers, optional single leader-owned worktree writer; leader is sole merge authority ([multi-agent-coordination](https://qwenlm.github.io/qwen-code-docs/en/users/features/multi-agent-coordination/)).
- **Agent Arena** (experimental): `/arena --models qwen3.5-plus,glm-5,kimi-k2.5 "task"` — up to **5** full top-level agents, each on a configured model in its own **git worktree** mirror of the working state (`~/.qwen/arena/<session-id>/worktrees/<model>/`); sequential launch, parallel execution, no inter-agent communication; in-process tab UI (tmux/iTerm2 split-pane planned); comparison phase shows metrics (duration, rounds, tokens, tool calls) + diff-overlap analysis; winner's diff extracted against baseline and applied; worktrees always cleaned up; no session resumption ([arena](https://qwenlm.github.io/qwen-code-docs/en/users/features/arena/)).

### 1.9 Permission mediation (daemon)

`MultiClientPermissionMediator` ([04](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/04-permission-mediation/)) resolves multi-client `requestPermission` votes under four policies: **`first-responder`** (default; first valid vote wins), **`designated`** (only the prompt's `originatorClientId` may resolve), **`consensus`** (N-of-M quorum, default `N = floor(M/2)+1`, `permission_partial_vote` progress events, issue-time voter snapshot), **`local-only`** (non-loopback voters refused). A `CANCEL_VOTE_SENTINEL` short-circuits under every policy, with two injection guards (`InvalidPermissionOptionError` on the wire, `CancelSentinelCollisionError` on agent-published labels). The **N1 invariant** arms the per-request timeout *synchronously inside `request()`* so an instantly-cancelled session can't leak a permanently-pending closure. Bounded 512-record resolved FIFO returns structured `already_resolved`. Documented v1 caveat: client identity is self-reported (no proof-of-possession).

### 1.10 MCP transport pool & budget guardrails (F2)

`McpTransportPool` in the ACP child keys entries by `(server-name + config-fingerprint)`, sharing **one** transport across all sessions that discover it; spawn-dedup via `spawnInFlight`; reverse `sessionToEntries` index for O(refs) release; idle drain timer (30s) with a 5-minute hard cap; operator `restartByName` publishes `mcp_server_restarted` with stable entry index; `drainAll()` on shutdown ([05](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/05-mcp-transport-pool/)). `WorkspaceMcpBudget` enforces per-workspace MCP budgets in `off`/`warn`/`enforce` modes with **hysteresis** and refused-batch coalescing; refused restarts carry typed reasons surfaced via capabilities ([06](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/06-mcp-budget-guardrails/)).

### 1.11 Provider layer

`modelProviders` settings declare per-auth-type model catalogs switchable at runtime via `/model` (hot-reloaded ~300ms debounce): auth types `openai` (incl. OpenRouter/vLLM/Ollama), `openai-responses` (reasoning replay via `reasoning.encrypted_content`), `anthropic`, `gemini`, `vertex-ai` (ADC support), `qwen-oauth` (hard-coded; **OAuth free tier discontinued 2026-04-15** — `/auth` now offers Alibaba ModelStudio (Coding/Token/Standard), third-party, custom). Custom provider ids map to protocols via `providerProtocol`. Credentials never persisted in settings — read from env. Per-entry `supportsImageGeneration`/`imageOnly` routes for the `image_gen` tool ([model-providers](https://qwenlm.github.io/qwen-code-docs/en/users/configuration/model-providers/)). A `fastModel` (set via `/model --fast`) powers the Auto-Mode classifier, recaps, and `model: fast` subagents.

### 1.12 Frontends

CLI TUI (Ink/OpenTUI), headless, ACP stdio (Zed extension uses this directly, bypassing the daemon), `qwen serve` + built-in **Web Shell** (same-origin browser UI; mobile via LAN QR), **VS Code companion** (daemon adapter, loopback-enforced), JetBrains, Chrome extension, **Desktop shell — Tauri (Rust) based**, with an `electron-migration.nsh` NSIS artifact evidencing an Electron→Tauri migration ([desktop-shell/src-tauri](https://github.com/QwenLM/qwen-code/tree/28df8b8a7897b0a8490220d00280c1c17d5ad002/packages/desktop-shell/src-tauri)) — *the brief's "Desktop Electron" is outdated*; **channels**: Telegram, WeChat, QQ Bot, DingTalk, DingTalk Workspace, WeCom, Feishu, GitHub, GitLab + extension plugin adapters — one shared ACP agent process, per-user session isolation, per-channel cwd/model/instructions ([channels](https://qwenlm.github.io/qwen-code-docs/en/users/features/channels/overview/)); SDKs: TypeScript (stable), Python & Java (alpha). **Computer use** via Rust `cua-driver` + `mobile-mcp` packages exposed as MCP-compatible boundaries.

### 1.13 Telemetry & evals

OpenTelemetry throughout: logs/metrics/spans, `qwen-code.*` metric namespace, Aliyun ARMS export or local file/collector, daemon telemetry middleware, daemon metrics ring ([telemetry](https://qwenlm.github.io/qwen-code-docs/en/developers/development/telemetry/)). **Public eval harness: none found** in repo or docs (integration-tests cover CLI/SDK/sandbox/hook/terminal behavior, not model quality) — UNVERIFIED absence.

## 2. Notable concepts (ranked)

1. **Daemon + ACP-bridge split as the multi-client substrate** — one `qwen --acp` child per workspace multiplexed to N clients over HTTP+SSE; agent execution is a separate process with NDJSON trust boundary. [01-architecture](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/01-architecture/)
2. **Multi-client permission mediation** — 4 vote-resolution policies, cancel sentinel with anti-injection guards, N1 timeout invariant, consensus quorum formula. [04](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/04-permission-mediation/)
3. **Prompt-cache-preserving fork subagents** — tool *restriction without declaration change* to protect the shared cache prefix; explicit "80%+ savings" claim. [sub-agents](https://qwenlm.github.io/qwen-code-docs/en/users/features/sub-agents/)
4. **Auto Mode 3-layer classifier approval** — acceptEdits fast-path w/ self-modification/persistence-path exceptions → safe-tool allowlist → two-stage LLM classifier (fast `shouldBlock` ~300ms → thinking CoT downgrade); broad allow rules auto-stripped while in Auto Mode; `softDeny` clears only on exact user intent. [auto-mode](https://qwenlm.github.io/qwen-code-docs/en/users/features/auto-mode/)
5. **Agent Arena** — competitive best-of-N across models in isolated worktrees with winner-diff apply; cross-provider model lineups in one command. [arena](https://qwenlm.github.io/qwen-code-docs/en/users/features/arena/)
6. **Workspace MCP transport pool + budget guardrails** — transport sharing by config fingerprint, refcounted idle drain, hysteresis budget modes. [05](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/05-mcp-transport-pool/)/[06](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/06-mcp-budget-guardrails/)
7. **Typed SSE event schema v1 with divergence-proof resync** — monotonic ids, ring replay, `state_resync_required` + SDK reducer delta-skipping. [10](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/10-event-bus/)

11. **LLM hooks** — `prompt` executor type makes the permission/extension layer itself model-evaluated, alongside command/http/function. [hooks](https://qwenlm.github.io/qwen-code-docs/en/users/features/hooks/)
12. **Worktree-first parallelism** — Arena worktrees, `enter/exit_worktree` tools, subagent `working_dir`, integrity-gated worktree session restore (`persisted-v1`, `409` taxonomy) in the daemon. [08](https://qwenlm.github.io/qwen-code-docs/en/developers/daemon/08-session-lifecycle/)
13. **Multi-protocol provider seam** — 5 protocols + custom-id→protocol mapping; `openai-responses` encrypted-reasoning replay. [model-providers](https://qwenlm.github.io/qwen-code-docs/en/users/configuration/model-providers/)
14. **Fail-closed conversation writer leases** — no force-unlock; boot-id/PID-ns identity proofs; operator-runbook recovery. [conversations-recovery](https://qwenlm.github.io/qwen-code-docs/en/users/conversations-recovery/)
