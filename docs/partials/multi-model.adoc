[[multi-model,Multi-model operation]]
= Multi-model operation

[[mm-adapters]]
== Provider adapters

Five adapters implement one dyn-safe Provider trait: Anthropic, OpenAI,
Google, xAI, and the OpenAI-compatible family (Ollama, vLLM, OpenRouter,
Groq). Streaming is resilient: mid-stream disconnects resume preserving
turn state with idle timeouts and exactly-once tool side effects — chaos
tests drop the stream at arbitrary bytes. Subscription OAuth device-flow
login (RFC 8628 + PKCE, refresh tokens in the OS keyring) is implemented
and cassette-tested in the providers crate — it is not yet composed into
the daemon's environment-based selection (the library-tested column of
the README status table). Models outside the cost table report tokens
only and an explicit unpriced state — costs are never invented.

[[mm-profiles]]
== Model profiles and dialects

Profiles are computed from transcript taxonomies: syntax and tool-misuse
rates, context-overflow and retry-storm behavior, edit rejections,
cost per turn — feeding behavioral axes (verbosity, thinking depth,
delegation preference, drift). Protocol dialects are explicit per profile —
thinking-content formats, usage semantics, tool-call identity rules — and
a per-model 400-trap feature-detection table records which request
parameters each model accepts (feature-detected per model, never per
provider). The failure this exists to prevent is documented: one wrong
dialect choice produced 72k characters of reasoning bloat where 6k was
intended (the dsh thinkingFormat bug, research §6; the elicitation
constitution, research §33).

[[mm-routing]]
== Routing that asks

Roles map to models — architect, editor, reviewer, hydrator, summarizer,
plus cheap-model utility roles (commit messages, session titles,
dedup-folding). Tasks pin their launch profile across resume; subtasks
inherit the parent profile, so models do not drift mid-task. Fallback is a
first-class primitive with an explicit verbatim chain and wait-out windows
for rate limits — and every hop is surfaced to the user. The daemon never
substitutes a model silently: an outage asks (our guard against the silent
failovers recorded in research §16 and §2). Model switches execute only at
compaction boundaries, where the cache miss happens anyway.

[[mm-routing-json]]
=== routing.json

Routing is configured by a single JSON document at
`{data_dir}/routing.json` (default `.austringer-daemon/routing.json`) —
read at daemon startup by the turn dispatcher. An absent document is
silence (the un-routed session model keeps serving); a present but
unusable one is loud and never fatal to inference. Every collection is a
list of keyed entries, so duplicate keys fail closed as typed build
errors instead of silently overwriting:

```json
{
  "provider": "anthropic",
  "cheap_pool": ["claude-haiku-5-5"],
  "roles": [
    { "role": "summarizer", "model": "claude-haiku-5-5", "effort": "low" }
  ],
  "tiers": [
    { "tier": "light", "model": "claude-haiku-5-5", "effort": "low", "score_floor": 0.0 }
  ],
  "categories": [
    { "category": "quick", "model": "claude-haiku-5-5", "effort": "low", "score_floor": 0.0 }
  ],
  "fallbacks": [
    { "model": "claude-opus-5-5", "chain": ["gpt-6-1-sol", "gemini-4-argon"] }
  ],
  "rate_limit_wait_out_secs": 45,
  "retry_attempts": 2,
  "benchmarks": [
    { "model": "claude-opus-5-5", "score": 91.0, "price_per_mtok": 15.0 }
  ],
  "sidekick": { "lead": "claude-opus-5-5", "sidekick": "claude-haiku-5-5" }
}
```

The policy keys: `fallbacks[]` lists rank-verbatim hop chains — the
order is explicit, never provider round-robin; `rate_limit_wait_out_secs`
caps rate-limit wait-out windows at 75; `retry_attempts` is the per
failure-mode retry count before an acknowledged fallback is *asked*.
Utility roles and the sidekick are validated against `cheap_pool` (a
utility role routed outside the cheap pool is a typed config error).
Fallback asks are mediated answers, not commands: a `FallbackAsk` rides
the protocol to the attached clients under the session's mediation
policy (first-responder by default, with a deadline), the timeout arm
retries the SAME model, and no client-asserted id can authorize an
answer. The `categories[]` entries define the `task(category)`
delegation vocabulary (see the delegation section below).

[[mm-subagents]]
== Subagents and the spec launcher

The spec launcher decomposes a written specification into objectives and a
task graph, launches heterogeneous models in parallel, and synthesizes with
a cross-consistency check — bounded by effort-scaling rules and hard budget
guards (no fifty-subagent spawns; burst quotas pace child spawns). The
launch path and fork-join children are wired into the daemon (child
sessions, write-set collision alerts, team events); best-of-N (the same
prompt on up to four models) and plan-branch comparison (the same spec
across models on snapshot branches) are library-tested and not yet wired
into the daemon loop. Children are ephemeral,
hidden from the main session list, and return capped summaries; they are
resumable by task id, and permissions bubble through the parent. A clean-
context reviewer reasons backward from the diff alone at milestones — zero
shared context, the attention-math pattern from research §22. Optionally,
tasks delegate to real Claude Code or Codex child processes through their
official protocols as additional launcher backends (opt-in, off by
default).
