[[leaderboard]]
== Release transparency — benchmarks

Every release publishes its benchmark numbers against the budget contract
(this page is the pre-release baseline; each tagged release adds its own
page under `docs/release/`). Publication rules:

* **Budgets are the contract.** The budget column is normative and
CI-enforced (`austringer-bench/budgets.json`); measured values are
machine-specific (recorded on the dev machine for this baseline,
re-measured by CI on every push) and presented as such.
* **Deterministic counters are regression-gated.** Wall-clock numbers ride
absolute budgets with min-of-N sampling; only machine-independent counters
are compared against committed baselines with a 10% tolerance
(`austringer-bench/baselines/gate_baseline.json`).
* **Reproducibility.** `cargo run --release -p austringer-bench --bin
perf-gate` re-measures every number below from source.

[[leaderboard-procedure]]
== Per-release procedure

. Build release binaries and run the perf gate against the committed
budgets and baselines (the CI job does exactly this on windows-latest to
match the baseline platform).
. Record the gate's JSON report (`--report`) as the release artifact.
. Add a page under `docs/release/` for the tag with the tables above
filled from the report; link it from the README release-transparency
section.
. If a deliberate change moved a deterministic counter, re-record the
baseline first (procedure in `austringer-bench/baselines/README.md`) and say
so in the release notes — silent baseline moves are not publishable.
